## Findings
### B1 (blocking): flag-off save after an M4-build session rolls progress back permanently
src/save/save.ts:154-155 (m4SaveSeq) with src/save/idb-mirror.ts:80 and :100.
An M4 build that runs pre-migration with the switch off (tracksOff → markM4BuildOff, game.ts:17/61) writes saveSeq on an unmarked farm. If that player then gets a flag-off build (a flag rollback), the flag-off build saves the unmarked farm without saveSeq (seq reads as 0). rankCompare ranks saveSeq above savedAt, which causes two problems:
(a) IdbMirror.write refuses to overwrite the IDB copy ("never over a higher-ranked copy"), so IDB stays frozen at the old copy.
(b) On the next boot, pickNewest/reconcile picks the old IDB copy and writes it over localStorage.
Every session after that is lost on reload. This breaks the PR #12 hadSeq / B1 rule that a newer write must never rank below an older one.
Repro (vitest, scratch): save() 5 times with markM4BuildOff(balance with m4.enabled 0) at coins 100 → seq 5 (= "idb"). Then save() with the plain flag-off balance at coins 999999 → no saveSeq (= "ls"). rankCompare(idb, ls) = 5 and pickNewest(ls, idb) = 'idb'. Both copies are valid.
Fix: carry saveSeq forward whenever the previous main (or IDB) copy had one (hadSeq), e.g. `saveSeqOf(prev) > 0 ? saveSeqOf(prev)+1 : (M4 condition ? 1 : undefined)`. Add a test for M4-build-off → flag-off → reload. Main builds (c197465) are unaffected because they reconcile on savedAt only, but returning to M4 after a main session whose IDB write was lost has the same shape. Check that case too.
