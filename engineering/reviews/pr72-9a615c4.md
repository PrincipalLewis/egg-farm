## Findings

### F1 (Major). The round-trip uses the run's flag-overridden balance, not the html's shipped balance, so `--flags m4.enabled=0` still PASSes with a migrated-farm screenshot
- **Where:** scripts/verify.ts:81, `saveRoundTrip(raw, run.end, b)`, where `b = withFlags(shipped, o.flags)` (:35). Related: verify.ts:78, where `markFreshM4(run.end, b)` returns the state unmarked when `b` has M4 off. The browser loads dist-html, which is built with the **shipped** balance (M4 on).
- **Repro 1 (CLI):** `npm run verify -- --hours 24 --flags m4.enabled=0` gives **exit 0, PASS**, with `saveRoundTrip.pass: true` and end levels F30/H0/V0/C30. verify.png (pr72-9a615c4-flagoff-verify.png) shows the goal pill "Egg value L21 · +6% income / Ready!" and +$1.6K/s: an M4 farm the run never had.
- **Repro 2 (node):** copy pr72-9a615c4-flagoff-repro.ts.txt to the repo root and run `npx vite-node pr72-fo.ts`. Output: `verify roundtrip (flag-off balance): pass true`, but `validate(raw, shipped)` gives F30/**H30/V20**, `tracksMigrated true`, and `saveRoundTrip(raw, run.end, shipped)` reports mismatches hensLevel 30≠0 and eggValueLevel 20≠0.
- **Why Major:** this is the defect R1 / VER-1a is meant to close, and `--flags` is part of the documented interface (HANDOFF and README). It is not Blocking: the default, PR-template and CI runs are correct, and no game code or save is affected.
- **Fix direction:** validate the round-trip with the balance the browser actually runs (`shipped`, or ideally the balance embedded in the built html). When the flags differ from the build, verify should either fail exit 4 (honest), or skip the browser step and record `screenshot: null, reason: flags differ from build`. Add a test with `--flags m4.enabled=0` that must not produce a PASS screenshot.

### N1 (Nit). Exit-code precedence is undocumented
- **Where:** verify.ts:125 / scripts/README.md:27.
- **Behaviour:** when the round-trip fails *and* another check fails (for example a build id mismatch), verify returns 4, not 1. That is fine, but README should say that 4 takes precedence over 1.
- **Repro:** test tests/verify.test.ts:164-178 (fake html with a wrong build id plus the marker skipped) exits 4.

### N2 (Nit). Mutant M6 survives: nothing pins that `pass` requires `!migrated`
- **Where:** roundtrip.ts:23. The suite has no case where migration happens while all 7 compared fields stay equal. Today every tracks migration lowers V, so a mismatch also fails it.
- **Repro:** change `pass: !migrated && mismatches.length === 0` to `pass: mismatches.length === 0`; `vitest run tests/verify.test.ts` stays 26/26.
- **Suggestion:** a unit case where `validate` reports `tracksMigrated` with unchanged levels (for example a crafted save whose price-match yields the same V), or one where `version !== SAVE_VERSION`, must give `pass: false`.
