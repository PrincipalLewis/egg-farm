**Verdict: PASS (0 blocking / 0 major / 4 minor / 3 nit).** No path found where a normal call signals a process outside the caller's lane tree, the `<=1`/self guards hold, and the start-time check correctly defeats ordinary PID reuse. Field parsing (`sed 's/^.*) //'` then `$20` = stat field 22) is right even for comm names containing `) `. The setsid comment is right: an `&` child in a non-interactive script is never a group leader, so setsid execs in place and `$!` is the session/group leader. The minors below should land soon after rollout; m-1 and m-2 are the only ones that touch "wrong process signalled".

## Minor
- **m-1 Start-time check is per-boot only (lane-kill.sh:15-17, lane-run.sh:17).** STARTTIME is clock ticks since boot, and pidfiles persist across reboots (two reboots this week). A pre-reboot record `P S` matches any post-reboot process that happens to get PID P with the same tick count. Low probability, but it is exactly the reuse case the rule promises to block. Repro (reasoning, not run): record a lane PID, reboot, any process landing on that PID at tick S passes. Fix: record `/proc/sys/kernel/random/boot_id` (or btime from /proc/stat) per line and refuse on mismatch; or truncate pidfiles at boot.
- **m-2 Pidfile record forgery via newline in arguments (lane-run.sh:18).** `echo "$pid $st ... $*"` writes arguments raw, so an argument containing `\n4242 123456` appends a second record that lane-kill's `awk '$1==p'` (lane-kill.sh:12) accepts. Repro: `lane-run.sh x -- sh -c $'sleep 1\n4242 123456'` then inspect `.pids/x.pids`. Still needs a matching start time, so mostly a hardening gap. Fix: `printf '%s %s %s %q\n'`-style quoting, or strip `\n\r` from the command field; have lane-kill only accept lines with exactly numeric `$1`,`$2` and a field-3 ISO timestamp.
- **m-3 Orphaned group is reported GONE with exit 0 (lane-kill.sh:14-16).** If the leader exits while children stay in group P (e.g. `sh -c 'a & b'`, wrappers that exit early), lane-kill prints `GONE P`, sends nothing and exits 0, so survivors keep running and the caller is pushed back toward ad-hoc ps/awk walks, which is the 23:21 failure mode. Repro (reasoning): `lane-run.sh x -- sh -c 'sleep 600 & exit 0'`, then `lane-kill.sh x <pid>` gives GONE, sleep survives. Fix: when /proc/P is gone, check for remaining members with pgid==P (read-only scan of /proc/*/stat field 5) and report `GONE P (N group members remain)` with rc=1; the kernel will not reuse P as a PID while group P exists, so a follow-up `kill -- -P` is safe.
- **m-4 Commands starting with `-` are parsed as setsid options (lane-run.sh:13).** `setsid "$@"` without `--`: `lane-run.sh x -- -f ...` or `-w` changes setsid behaviour; with `-f` the recorded PID is the short-lived setsid parent and the real process is untracked. Fix: `setsid -- "$@"` (util-linux accepts `--`).

## Nit
- **n-1 TOCTOU between check and kill (lane-kill.sh:15-21).** Start time is checked, then `ps` forks, then `kill`. Reuse inside that window needs a full 4.19M PID wrap, so negligible; a pidfd-based kill would close it.
- **n-2 Integer wrap in PID parsing (lane-kill.sh:10-11).** `18446744073709555858` wraps to `4242`. It still has to pass the lane pidfile + start-time check, so no cross-lane effect; add a length cap (`^[0-9]{1,7}$`).
- **n-3 "exited immediately" never fires (lane-run.sh:15-16).** The child stays a readable zombie until lane-run exits, so a failed exec (e.g. command not found, 127) is still recorded and printed as a PID. Not a safety issue.

## Observations (policy, not code defects)
- **O-1 Lane identity is honour-system.** Every agent runs as uid `box` and `.pids/` is writable by all, so any caller can name another lane or append to its pidfile. The script protects against accidents, not against a misbehaving agent; the README/rule text should say "your own lane" is a convention.
- **O-2 Claude exception isn't enforced.** A group kill hits every member of the lane's process group, including any Claude Code process a lane-run'd tree spawned. The tools rely on the README rule that Claude processes are never wrapped; consider a refusal if any group member's comm/exe is claude.
- **O-3 Escaped sessions leak, they are not mis-signalled.** Children that call setsid themselves (browsers launched detached by Playwright, some daemons) leave the group and survive the group TERM. Lanes need to stop those through the runner's own shutdown, not via ps walks.
