## Rulings
1. **`Game.markClockWageTip()` emitting `tip_shown` (game.ts:353-356): OK, keep in Game.** On rc/v5, UI-impression/tip events are tracked from the shell, not the sim (`coop_hand_tip` app.ts:166/757, `ios_home_tip_shown` app.ts:854). G0's "only the sim emits" covers Refill *sim* events (refill_used, rest_toggled…); a tip impression is not sim state change. Game is better than app.ts here because the save flag write and the event are atomic in one method. Condition: the UI must not also track it (it doesn't).
2. **Welcome-back per-role totals across reload: second optional save key, Saves-owned.** AC-FC12 requires reload survival, so a view over in-memory data cannot satisfy it. Shape (proposal for Saves): `clockWageWindow?: Partial<Record<'market_hand'|'coop_hand', {asleepMs:int, cents:int}>>` in `M5_SAVED_FIELDS`, sanitiser in `m5Load` (non-object/negative/non-integer → entry dropped), absent when empty, flag-off ignored and written back verbatim (E13 pattern), no SAVE_VERSION bump (HoE no-bump rule; additive optional v6), red-first v5→v6 round-trip + flags-0 write-back test. Ticked in step() (live sim only; reverts with the hide snapshot; offline never steps = FC-R5), reset by a sim reducer on welcome-back close (`collectOffline`/`dismissOffline`), flag-gated. Hire 2 builds the tick/reset; Saves owns key + sanitiser.
3. **Pause rule 8 / AC-P12 (manage vs paused).** rc2Refill = 0: per-card Manage on a paused worker works under its normal rule (≤ threshold, shared cooldown), refills to 100 **and ends the pause** through `resumeWorker`, so the Market Hand gets B5 `callLockoutS` = 45 s (pause rule 8 L153-155, rule 7 L134-137; D-PMW-2026-11-10-01 Q1; D-HOP-2026-11-10-20 7.5 "every resume, incl. manage") and emits `worker_resumed{cause:"manage"}` (§12 L304/306; AC-P12 L333). Manage all skips paused workers and `needManage` excludes them ("N shows 1", rule 8 L156; AC-P12); the R9 reserve excludes paused (rule 10). **This is already built in Saves' open PR #119** (8ee3db1 → fd64aa6: actions.ts:109, workers.ts:28/36-46), so: owner Saves, ship via #119; Hire 2 changes nothing in sim; Saves must not re-implement it in the worker_paused emitter PR (rebase onto #119 instead). rc2Refill = 1: `manage`/`manageAll` are sim no-ops (D-HOE-57 7.6), the card Manage opens the Shift sheet (7.9); a Refill on a Paused/Rested worker ≤ 50% refills and ends Rest via `resumeWorker` with B5 (7.4/7.5) and emits `rest_toggled{on:false,cause:"manage"}` (pause §12 L306); > 50% is blocked `above_threshold` (7.8). Owner Saves (Refill reducers). None of these paths writes cdS (FC-R1 U1) — keep it that way.
4. **`asleep_time` internal SimEvent: not OK; make it a state accumulator.** The SimEvent union is the sim→shell contract; a 20-per-second bookkeeping event that every consumer must filter (game.ts:140, the telemetry-schema NOT list) is the wrong tool, and it can't satisfy ruling 2 (persistence) or session reset cleanly. Follow #119's `tickPausedFor` pattern: one pure writer `tickAsleepClock(s, ws, dtMs, b)` called once in `step()` after the energy loop, gated by one exported predicate `asleepClockOn(b)` (today `clockWageOn(b)`; Refill later ORs in autoRefill — one-line change, no second writer), integer ms. Session total in a never-saved `M5_SESSION_FIELDS` key (asleep worker-ms), per-role window in the saved key of ruling 2; wage cents for the window added in the same place the asleep wage is charged (clockWageAsleepStep). Game reads pure views for `session_end`, and a pure `resetAsleepSession(s)` runs at session rotation (shared with Refill's G0 M2 reset). Emit `asleep_s` when `asleepClockOn`, `wage_paid_asleep_cents` only when `clockWageOn`, both independent of rc2Refill.

**D-HOE-57 amendment check (Hire 2 owns asleep_s):** the S1/S2 seam supports it. The S4 build as-is does not yet (duplicated gate, Game-private writer, no reset, float); with ruling 4 it has a single writer API Refill can extend for autoRefill without touching clockWage code, and clockWage/autoRefill stay independently switchable.
