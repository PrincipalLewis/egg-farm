## (1) Trigger
- `src/ui/app.ts:701` sets `g.onTracksCommitted = () => showTracksExplainer(g)`. game.ts:222 fires it after the commit is read back.
- `src/ui/app.ts:702` adds the on-load case: `if (g.tracksMigratedWithBackup) showTracksExplainer(g)`.
- No double-fire: `showTracksExplainer` sets `seenTracksExplainer = true` and calls `g.save()` synchronously before it renders. A second call, from either path, returns null.
  - A save still pending at boot has no committed backup, so the on-load path is false. A committed save has `tracksPending` null, so `onTracksCommitted` never fires.
  - Covered by tests/m4-exp1-explainer.test.ts:39-62.
- **Reload:** the browser probe loaded the F30 fixture on the M4-on QA build. The card showed, `seen` was persisted at show time, and after a reload the card count was 0. A reload after commit but before the card ever showed does re-show it, once (test :55-62).

## (2) Fresh farms
- A fresh M4 farm gets `tracksV7:1` and a new `v6BackupId` (game.ts:75) but no v6_backup record, so `isCommittedBackup` is false and the card never shows. Test :63-68.
- After Reset, `v6_backup` is in RESET_KEYS, so the same holds.

## (3) Persistence
- `seenTracksExplainer?: boolean` is optional (state.ts:26) and SAVE_VERSION is still 6.
- Old saves without the field validate fine.
- The field round-trips through serialize/validate with the flag on and off, the checksum covers it, and a flag-off load followed by a save keeps it (test :69-85).
- validate() has no key whitelist, so older builds carry the field through unchanged (the same mechanism #47's "unknown fields kept" test shows).
- saveSeq and rank are unaffected: `rankOf` reads only version, the marker and saveSeq. Setting the field goes through the normal `g.save()` (saveSeq +1).
- The mirror and reconcile carry the raw save string, so the field rides along.

## Findings
- **m1 (Minor)** src/ui/tracks-explainer.ts:13: `seen` is persisted when the card is shown, not when it is dismissed. A reload, crash or tab close in the first 8 s means the player may never actually read it.
  - Repro: load the F30 fixture on the M4-on QA build, wait for the card, reload, and the card is gone.
  - This matches the amendment's "shown once", but HoP or Art & UX should confirm that shown-once rather than dismissed-once is the intent.
- **m2 (Minor)** src/ui/tracks-explainer.ts: there is no test that the overlay leaves the Market Hand or the tick running while it is open. That holds by code inspection only. Suggest a unit test that steps the sim with the card open.
- **n1** src/ui/tracks-explainer.ts:10: the doc comment says "Call ONLY from Game.onTracksCommitted", but app.ts:702 also calls it from the load fallback. The comment is stale.
- **n2** the base's l30plus.test.ts depends on an uncommitted staging CSV, so `npm test` is red on base and head alike. HoE should track this with #45's data delta.
