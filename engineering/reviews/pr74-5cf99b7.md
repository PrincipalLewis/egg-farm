- Suggested tests:
  - (a) A real tsc break in a temp copy (or a `VERIFY_BUILD_CMD`-style hook) must exit 3 with `stage:build`. This kills M31.
  - (b) Default dir: seed `verify-out/<HEAD id>/verify.{json,png}`, run a usage error, expect a FAIL json and no png. This kills M28/M29.
  - (c) Spawn a long run, SIGKILL it after the first log line, and expect no verify.json/verify.png. This kills M17–M19.
  - (d) `--skip-build` with an html of another id, then a crash, expects that dir cleared. This kills M33.
  - (e) Optionally, a throw hook after the browser step to kill M27.
- Not blocking, because there is no correctness risk in the shipped code.

### N-c (Nit). A failure inside writeEarly hides the original error, and on early exits turns 2/3 into 1
- File: scripts/verify.ts:166-172 (`catch` → `writeEarly(ctx, 1)` before `throw e`; also `writeEarly(ctx, code)` at :172 is unguarded).
- Repro 1 (sandbox C8): make `<out>/verify.json` a directory → rmSync in claimOut throws first, then writeEarly's writeFileSync (:161) throws EISDIR from :169. stderr shows only the EISDIR stack, not what failed first.
- Repro 2: mutant `throw` as the first line of writeEarly + `VERIFY_TEST_THROW=1` → the stack shows only "MUT in writer". With `--hours 0` the result is exit 1 instead of 2.
- It still fails safe: the exit is non-zero and nothing stale is left.
- Fix: `try { writeEarly(...) } catch (w) { console.error('verify: could not write FAIL report:', w) }` in both places, keeping the original code or error.

### Observations (no action required)
- **O-1:** `--out` is created (recursively) before the args are validated, so a usage error with a typo'd `--out` leaves an empty-but-FAIL dir (C10). This is documented (README:46).
- **O-2:** The default dir is keyed by the HEAD build id before the build. On a dirty tree, the earlier clean-id dir keeps its (correct, for that id) PASS report, while the `+dirty` dir is the one cleared. This is documented (README:47).
- **O-3:** `m4.enabled=2` simulates identically to `=1` (same trace 00a17ba6 at 0.1 h). Values other than 0/1 are accepted by `--flags` and only caught by the exit-4 build comparison. That's fine for this PR.
