## New findings

| # | Sev | Finding | Where |
|---|---|---|---|
| N1 | Minor | Main pushes are no longer cancelled while in progress, but the default concurrency `queue: single` keeps at most one *pending* run per group and cancels and replaces any existing pending run. | ci.yml:19-22 |

**N1 detail:**
- **Failure case:** merges A, B, C to main land within one gate + FF/WK window (about 12-30 min). A runs, B goes pending, then C arrives: **B is cancelled** and C goes pending.
- **Wording:** the comment at :19-20 ("main pushes queue instead of cancelling, so every main SHA gets a verdict") and the PR body overstate this. The PR body even notes "GitHub keeps only one pending run per group".
- **Fix (cheapest):** key push runs on the SHA, so each main commit has its own group:

  ```yaml
  group: ${{ github.workflow }}-${{ github.event.pull_request.number || github.sha }}
  ```

  - Main runs would then execute in parallel. That is fine: there is no deploy step, and standard runners are free on a public repo.
- **Avoid `queue: max`:** GitHub rejects `queue: max` combined with `cancel-in-progress: true`, and actionlint 1.7.7 predates the key.
- **Alternative:** accept the behaviour and fix the comment.

There are no other new findings. Lint and security:
