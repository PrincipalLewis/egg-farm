## 3. Save migration v6 → v7 (v0.2: dual-write by flag, ADR M4-4)
**Schema (v7 adds):** `hensLevel:int`, `eggValueLevel:int`, `celebratedMilestones:string[]`, `migrationRefundCents:int (default 0, ≥ 0)`, `v6BackupId:string (16 hex, set at commit, ADR M4-15)`,
`seenTracksExplainer:boolean`. Nothing else changes; `collectionLevel` keeps paid levels.

**Interim (ADR M4-8, 9.8): `tracksV7` marker inside v6.** `m4/m4a-tracks-v2` @ `3351d6c` keeps `SAVE_VERSION = 6`. With M4 on, a save with no
`tracksV7` marker (v1..v6) is price-matched once through `migrateTracksV7` and gets marked `tracksV7: 1`; new M4 farms are marked at creation.
This is allowed **only in playtest and M4-flagged builds, never as a release default**. Flag-off builds must load a marked save normally
(ignore or keep the marker and track fields) and must **never strip them on write**. S-2 is unaffected because a marked save is still v6.
**At `3351d6c`, M4-on saves are v6 with `tracksV7: 1`; v7 plus the kept `v6_backup` only arrive with S-4.** The v7/`v6_backup` text below describes S-4, not v2.
**Interim backup (9.9, ADR M4-10):** before the in-place price-match, the interim path's caller writes the original validated raw v6 bytes to `v6_backup` (same keys and protocol as S-3, §3c; write-once only once committed, ADR M4-15). The interim path **never refunds**: `migrateTracksV7` returns a refund (0 with current data) that F-0 must not apply; S-4 computes and records it in `migrationRefundCents` (m5). Owner: Features 95daf662.

**Write version follows the flag (9.2):**
- `m4.enabled = 0` (all shipping builds until M4 reaches Latest): reads v6 and **writes v6 only**. A **v7 save is refused exactly like a newer save** (ADR M4-9, 9.7): the existing `.newer-save` dialog, S-2 zero-writes rules, never writes v6 over v7, never silently drops M4 progress. `v6_backup` stays as the escape hatch; export stays available.
- `m4.enabled = 1`: reads v6/v7, migrates v6 → v7 and **writes v7**. `eggfarm.save.v6_backup` (once committed, ADR M4-15) is **kept until M4 reaches Latest**; it is cleared only by Settings > Reset (m2).
- So `SAVE_VERSION` splits by a **runtime gate (ADR M4-14, N4): `m4Active = m4On(b) && committed`**, held in `Game` (session state, not storage). `committed` is true when the loaded save is v7 or a marked v6 with a `v6BackupId`, or once this session's migration commits (§3c); it never goes back to true after an abort in the same session.
  - `readMax(b) = m4On(b) ? 7 : 6` uses the **build flag** (an M4-on build can always read a v7; flag-off refuses v7).
  - `writeVersion = m4Active ? 7 : 6`, and on the interim path the `tracksV7` marker is written only when `m4Active`. M4 formulas (`m4On` call sites in sim/econ), the tracks UI and track purchases gate on `m4Active`. So a pending or aborted session serializes plain v6 and plays v6 rules (test: aborted session's stored bytes are v6, no marker, no track fields changed).

**Migration function** (S-4, the real bump) `migrations[6] = (d, b) => v7`, run only when `writeVersion(b) = 7`. Three inputs:
- **unmarked v6:** full migration (steps 1–5 below);
- **marked v6** (`tracksV7: 1`, track fields present): just bump the version. Keep the levels, no new price-match; record the refund the interim path did not apply (recompute it from the frozen price table into `migrationRefundCents` + `coinsCents`; 0 with current data), so it is never dropped; no explainer or `save_migrated` replay. Idempotent;
- **v7:** no-op.
Steps for the unmarked path, calling pure `migrateTracksV7(state, b, opts?)`:
1. `hensLevel = farmLevel`.
2. `eggValueLevel` = lowest V in 0..`b.maxLevel` (no F+3 cap, B1; today 30 from data, never a literal) with v7 price ≥ v6 price in integer cents (one half-up rounding, M4A-5). **If no V reaches it, V = the track max level** (m5).
3. Clamp only above `maxLevel`, **read from data** (`balance.maxLevel`, generated from economy.csv into balance.json and validated in `config/balance.ts`; **never a hard-coded 30**; L30+ content is coming); refund the removed levels at the CSV cost column into `coinsCents` + `migrationRefundCents` (0 with current data). **Money rule (m5):** each level's cost is integer cents (`Math.round` once per level, as `formulas.ts` does for costs); the refund is a non-negative integer; `coinsCents + refund` is clamped to `Number.MAX_SAFE_INTEGER`; the validator rejects non-integer or negative `migrationRefundCents`.
4. Seed `celebratedMilestones` silently.
5. Mark "migrated this session" (explainer unlock); emit `save_migrated` once (interim F-0: `{from: 6, to: 6, migration: 'tracksV7_marker'}`; S-4: `{from: 6, to: 7}`). **Offline grant with the in-session commit (m4/N5, ADR M4-16):** the offline grant runs at boot, before any migration, under flag-off rules (`m4Active` false ⇒ Hens offline mult ×1.0, v6 egg rate). That *is* the M4A-30 "first grant after migration ×1.0": it is satisfied by construction, so no `firstGrantDone` field is stored. The next load after commit grants with the M4 Hens mult. Effect on M4A-30's order: "migrate → grant ×1.0" becomes "grant ×1.0 (v6 rules) → migrate in-session"; S-5 re-derives its expected values (19800 at the boot grant, 24750 on the following load) and HoP notes it in the spec. An abort leaves the save untouched and the retry's boot grant is again ×1.0. Pending offline eggs from the v6 save are settled before migration (game.ts:54 order kept). Float order is the code's, pinned: `Math.floor(Math.min(awayS, cap) * offlineRateMultiplier * eps)` (src/sim/offline.ts `offlineEggs`, a01faea), with ` * mult` appended last on the M4 branch (3351d6c offline.ts:9); left to right; tests use 1.35-type multipliers. **Payouts:** every multiplied payout (milestone × balanced × grader) is computed in integer cents and clamped to `Number.MAX_SAFE_INTEGER` (nit).
The chain must receive `balance` (S-1).

**Level clamp from data (M4A-27):** the load/validate clamp and range checks for `farmLevel`, `hensLevel`, `eggValueLevel` and `collectionLevel` use `0 ≤ level ≤ b.maxLevel` (and the per-track max from the same data), never a literal. Raising the max in economy.csv raises the clamp with no code change.

**Load order (ADR M4-17):** read the copy that wins reconcile/recovery → version > readMax(b) ⇒ refuse (zero writes; flag-off + v7 included) → **parse → version → checksum → ranges** (pure validation, split out of `validate()` so it no longer runs `migrate()` first). Corrupt or out-of-range ⇒ the existing corrupt-recovery path; **never migrated, never backed up** → the game boots and runs this v6 **synchronously under flag-off rules** (§3c) → if M4 on and the save is an **unmarked** v6: the async backup + migration protocol of §3c (a marked v6 or a v7 save writes no new backup).
The bytes backed up are the **original raw validated bytes of the copy actually loaded** (LS main, or the `.bak`/IDB copy that recovery chose).

**Backup-write failure = ABORT the migration (ADR M4-12; spec M4A-31(a)/(f)1 governs; supersedes the 9.1 "keep playing migrated" rule and M4-10/M4-11 "IDB best effort"). IDB *definitely absent* is not a failure; an IDB timeout or read error defers the migration (ADR M4-16, §3c).**
If the v6 backup write fails in localStorage, the LS read-back does not match, or IndexedDB is present but its open times out, its read or write fails, or the write does not complete within 1500 ms:
- do not migrate; keep the v6 state in memory and keep **flag-off rules for the rest of the session** (`m4Active` false, ADR M4-14);
- save v6 normally (main, `.bak` rotation, IDB mirror) with **no `tracksV7` marker** and no v7;
- show the v2.2 "Can't save" notice (once per session, then the toast) **only if that normal v6 save also fails**;
- retry the migration on the next load.
The same rule applies to the interim marker path (F-0) and the S-4 v7 path: the backup must be confirmed (LS required; IDB too when available) before the migration commits.
**Partial backup (ADR M4-13, made robust by M4-15):** if one store's backup write succeeds and the other fails, the aborted attempt tries to remove **only the backup records it wrote** (matching its `migrationId`). The cleanup is best effort (removeItem can throw, the IDB delete may not finish before pagehide); correctness never depends on it, because an unreferenced backup is an orphan (§3c) and only the next migration attempt overwrites it. **Quota (M4-23):** after an abort, if a normal save hits quota, the game first removes the leftover LS backup record **whose `migrationId` equals this session's aborted attempt** (never the one main's `v6BackupId` references, and **never the only pre-M4 backup**) and retries the normal save once; if there is still no room without it, the save defers or fails visibly via the existing quota path ("Can't save" notice), never by dropping that backup, so the backup can never push the normal save over quota.
Emit `save_migration_aborted {store, reason, path}` (§5; the one field set used everywhere).

### 3c. Backup + migration protocol (ADR M4-14..17)
- **Aborted / pending session = flag-off rules (M4-14).** From boot until the migration commits, and for the rest of the session after an abort, the game runs the v6 state with flag-off rules: M4 formulas off, Farm-tab tracks UI, best-buy and track purchases hidden/disabled, the save stays plain v6 (no marker, no track levels written). So no track purchase can exist that the next migration would overwrite.
- **Commit marker (M4-15).** Each attempt draws a random `migrationId` (16 hex chars) **in `save/`** (`crypto.getRandomValues`, fallback `Math.random`) and injects it as `opts.migrationId`, so `migrateTracksV7` stays pure; tests, fixtures, the 961-save sweep and the storage golden pass a fixed id. The backup record is `{"migrationId":"<id>","raw":"<original v6 bytes>"}` in LS `eggfarm.save.v6_backup` and IDB `eggfarm/save/v6_backup` (QA unwraps `raw` for byte compares). The committed save stores the same id in `state.v6BackupId`: **S-4 in the v7 save, and F-0 in the marked v6 save** (so the interim backup can be committed, N3). A backup is **committed** only if its id equals the live save's `v6BackupId`; otherwise it is an **orphan**: not restored, not write-once-protected. Saves already marked at 3351d6c (playtest only) have no backup and no id; they are documented as uncovered and S-4 treats them as marked v6.
- **Orphan handling (N2, HoE-approved, final).** An orphan is deleted or overwritten **only inside the unmarked-v6 migration path, at the moment that path writes a fresh backup**. Never on a plain load, a refused load (§3b zero writes), a corrupt-recovery load, a `.bak` restore or a fresh farm, and never a record whose id is referenced by main, `.bak` or IDB main. **Exception (M4-23, N2):** after an abort, the quota cleanup may remove the leftover backup whose `migrationId` equals **this session's aborted attempt**, and never the record main's `v6BackupId` points to; it **never deletes the only pre-M4 backup** (the sole record holding a pre-M4 raw). The IDB put is conditional inside its transaction: it does not replace a record whose id is referenced by a committed save (a late write from an older attempt cannot clobber a committed record).
- **IndexedDB (M4-16, HoE-approved, final; supersedes the 2000 ms rulings).** The LS backup is **required**. IDB is *definitely absent* only when there is **no `indexedDB` global, or `open` throws / rejects synchronously or with a private-mode or `SecurityError`**. Then the attempt proceeds on LS alone (read-back still required) and emits `save_backup_idb_unavailable {reason: 'no_global'|'security', path}` (§5; `security` = `SecurityError`, `InvalidStateError` and private-mode errors, spec **v1.9** M4A-31(g)). **`blocked` (`onblocked`) is a deferral** (`reason: 'idb_blocked'`), not unavailable: IDB exists and may hold a newer save (M4-20; spec **m4a-spec v1.9** M4A-31(f)1/(d1), HoP decisions.md 22:09: `idb_blocked`, `attempt_count` +1). `IdbMirror.open` must be refactored to return a tri-state result `{absent|security|blocked|timeout|error, db}` instead of null for everything. Spec m4a-spec **v1.7 M4A-31 (f)1/(g)/(d1)/(h)** (HoP-approved) governs. Any other outcome is *unknown* and **defers** the migration: open not answered within **T = 1500 ms** (the existing mirror timeout; an answer at 1499 ms is available; **covers the IDB open only**, spec v1.10) ⇒ **deferral** `save_migration_aborted {store: 'idb', reason: 'idb_timeout', path, attempt_count}`; any other open or read error ⇒ `reason: 'idb_read_error'`. A timeout is always a deferral, never "unavailable". Deferred = stay v6 under flag-off rules, retry next load (spec (d1)). Once open, a backup write that fails ⇒ abort `reason: 'quota'|'error'`; a write still pending after 1500 ms ⇒ abort `reason: 'idb_write_timeout'` (spec (h)).
- **Attempt counter (spec v1.7 (d1)).** LS key **`eggfarm.save.migration_attempts`**: a **plain non-negative integer** (decimal string), **capped at N = 3**: at the cap it stops incrementing and `stuck_on_v6: true` is set. It must never hold a serialized save object (§3b); a parse failure or non-integer value is reset to 0. **Every failed attempt increments it**, [abort] or [deferral] (spec **m4a-spec v1.12**, AC (h)6: three consecutive `commit_write_failed`/`readback_mismatch` reach `stuck_on_v6` on the 3rd), capped at 3. **`stuck_on_v6` is a separate LS key `eggfarm.save.stuck_on_v6` (`1`)**, not reset by the garbage-to-0 counter rule; it is removed on commit and by Reset. **At the cap (F3)** the game shows a **one-time non-blocking notice** offering **Export save** (show-once flag in its own LS key `eggfarm.save.stuck_notice_shown`, never written on a refused load, cleared by Reset) (the same raw export as ZW-2); the migration is never forced. Accepted risk: while the mirror is off (deferral sessions) IDB main goes stale; the M4-19 divergence rule keeps both copies. It is **removed on commit**, cleared by Reset (`RESET_KEYS`), and **never written on the refusal path** (§3b). At `attempt_count = 3` (the cap) the event carries `stuck_on_v6: true`. The migration is **never forced** at any count. Why: an IDB read that times out may hide a newer IDB-only save (old B1 class); migrating the LS copy would overwrite it. The 2000 ms open/write timeout (HoE ruling 21:58, spec v1.6) is **superseded** by spec v1.7. S-3 adds an `onblocked` handler so `blocked` can be detected and deferred.
- **LS read-back (M4-16, HoQA bar).** After the LS `setItem`, `save/` reads `eggfarm.save.v6_backup` back and parses it; its `migrationId` must equal the pending `state.v6BackupId`. Mismatch, parse failure or a throwing `getItem` ⇒ abort under M4-12: stay v6, no marker, `save_migration_aborted {store: 'ls', reason: 'readback_mismatch', path}`.
- **Async, in-session commit (M4-16).** Boot is unchanged and synchronous (v6, flag-off rules, `m4Active` false). After boot `save/` writes the backup and commits in this order, with the lease/resetting/newer guards re-checked before each step (review 677317d m1; the main write is the dedicated commit write, M4-21):
  1. LS backup record (sync) → LS read-back check;
  2. IDB backup record (awaited with a keyed success result added to `IdbMirror`; the current fire-and-forget `write` is not enough), skipped only if IDB is definitely absent;
  3. **[S-4 as written; under §3d (M4-A) the commit writes LS only]** at the next tick boundary: **re-read IDB main**; if it is newer under the rank rule (M4-19) or the read fails ⇒ **deferral** `idb_main_changed` (spec (d1)8; `attempt_count` +1). Migrate the **boot input** (M4-20), set `v6BackupId`, then write main (v7, or marked v6 on F-0) with a **dedicated `save/` commit write** (M4-A: LS-only `commitWrite(kv, raw) → ok|fail`; **the two-store form `{ls, idb}` is S-4**), **not `Game.save`**: it re-checks resetting/lease/newer first, has no quota fallback that would write the migrated state to IDB, and any skip or per-store failure aborts `commit_write_failed` (M4-21);
  4. (counter removed before the IDB main write, so a kill cannot leave it stale) set `m4Active = true`; the M4 UI unlocks in this session and the M4A-33 explainer shows now (the "first load after migration" becomes "the moment the migration commits"; HoP spec note).
  **Commit-write failure (N6):** if the main write in step 3 fails (quota is likeliest, the backup roughly doubles the footprint), keep the old main untouched, revert memory to the pre-migration v6 state, `m4Active` stays false, emit `save_migration_aborted {store: 'ls', reason: 'commit_write_failed', path}`; the backup is an orphan and is replaced at the next attempt. **Close between writes:** the backup is durable first (LS `setItem` is synchronous and precedes main), so a kill at any point leaves either old v6 main + orphan backup (retry next load) or committed main + committed backup; never a v7/marked main without an LS backup. Residual risk: a browser that lazily flushes LS could persist main before the backup; with IDB absent there is then no second copy. Accepted, noted in §7.
- **Save ranking (M4-19, B1).** Every comparison of stored copies (the newer-save check, `pickNewest`/reconcile LS vs IDB, and export, §3a.3) ranks by **(1) version, (2) committed (`tracksV7`/v7 with a `v6BackupId` beats an uncommitted copy), (3) `saveSeq` (missing = 0), (4) valid `savedAt`**; savedAt only breaks the last tie. Today `pickNewest` compares savedAt only (idb-mirror.ts, a01faea), so a stale LS copy autosaved later beats a newer IDB v7. The IDB main put becomes conditional inside its transaction on the same rank. **N1 fixed (HoE 22:20): rank = version → committed → `saveSeq` → savedAt.** `saveSeq` is a monotonic save counter in the save file, incremented on every successful write (missing ⇒ 0); two v6 copies are compared by `saveSeq` before savedAt, so a stale LS v6 autosaved later in a deferral session (lower `saveSeq` than the newer IDB copy the mirror absorbed) no longer wins. **Main gets the same fix in a separate small `save/` PR (task SQ-1, owner Saves 3ba38cf3), which M4 depends on.**
  **`saveSeq` validity (F2):** a safe integer 0..2^53−1 (`Number.isSafeInteger`, ≥ 0); anything else is treated as 0. It lives **inside checksummed `state`**, and older and flag-off builds preserve it unchanged on write (they spread unknown state fields).
  **Divergence (M4-19 amendment, HoE + Saves 22:44; revised HoE 23:25).** Each write stamps `state.base = {seq: saveSeq read at boot, idbUnknownAtBoot, forSeq: saveSeq of this write}`. A base is **trusted only if `base.forSeq === copy.saveSeq`**; a mismatch (an older or flag-off build preserved the field but bumped `saveSeq`) means the base is ignored and plain ranking applies, so stale flags never count. Two copies have **diverged** only if one has a trusted base with `idbUnknownAtBoot = true` **and `base.seq < ` the other copy's `saveSeq` (strict)**. Not diverged ⇒ rank as above (version → committed → `saveSeq` → savedAt). Diverged ⇒ the copy **without** `idbUnknownAtBoot` wins regardless of `saveSeq` (it was written with knowledge of both stores).
  **One ordering (M-6):** F2-EQ only chooses the winner for equal `saveSeq`; it never preempts slotting. Every case below that has different bytes is **diverged**, and its loser always takes the full slot path (newer-version check → slot write + read-back → overwrite) with `save_copies_diverged`; a loser is never overwritten unslotted (D-2).
  **Equal `saveSeq` (F2-EQ, option (a); checked first):** two copies with the **same `saveSeq`**:
  - **byte-identical** ⇒ not diverged, nothing moves;
  - **different bytes**, and **exactly one** copy carries a trusted `idbUnknownAtBoot` (Code Reviewer (c)) ⇒ **diverged**; winner = the **known** copy (decided by the unknown flag alone, never by `savedAt`); the unknown copy is the loser and goes through the full slot path with `save_copies_diverged`;
  - **different bytes**, and **neither or both** copies carry a trusted `idbUnknownAtBoot` ⇒ **diverged**. Winner = the later valid `savedAt`; if `savedAt` is also equal, the deterministic tie-break is **the LS copy wins** (primary store). The loser goes byte for byte into a slot with read-back before any overwrite, under the two-slot rules below (fill an empty slot, else replace the lower-`saveSeq` slot via `diverged_tmp`; no skip path).
  **Not diverged (F2):** otherwise, if **both** copies carry a trusted `idbUnknownAtBoot`, they are **not diverged**: plain ranking applies and the slots are untouched. In normal operation only one copy can carry the flag (IDB main is never written in an IDB-unknown session, M4-20), but a rollback to a pre-SQ-1 build can leave both copies with a preserved, still-trusted base.
  **Pre-SQ-1 builds (F2):** an a01faea-era build does not know `saveSeq` and preserves `saveSeq` and `base` unchanged (state spread), so `forSeq === saveSeq` can still hold; the both-unknown rule keeps such copies out of divergence, and equal-`saveSeq` copies diverge only when their bytes differ (F2-EQ), in which case the loser is kept in a slot. Post-SQ-1 flag-off builds bump `saveSeq` and so fail the `forSeq` check.
  **Recovery slots (HoE M1/M2; v0.3.9 SK-1, ADR M4-19 rev 4).** Two IDB slots, **`eggfarm/save/diverged`** (slot 1) and **`eggfarm/save/diverged2`** (slot 2), each holding one loser **byte-for-byte** (the exact stored string, D-2). Pre-SQ-1 and other non-SQ-1 builds never read, write or delete either key. Order on a load that finds divergence:
  1. the newer-version check runs first; a **refusing load never runs the divergence move and never writes or clears either slot** (Export included);
  2. pick the target slot: an empty slot (slot 1 first, then slot 2); if both are full, the slot holding an **exported** copy (`exportedAt` set; lower `saveSeq` first if both are exported), else the slot whose copy has the **lower `saveSeq`** (equal ⇒ slot 1). **Slot record (Code Reviewer (a)):** each slot/tmp value is `{bytes, exportedAt}`: `bytes` is the loser's exact stored string (all byte-for-byte and read-back comparisons are on `bytes`), `exportedAt` is null or the epoch ms of a confirmed export. **Legacy values (S-10):** a slot or tmp value stored as a plain string is read as `{bytes: value, exportedAt: null}`; it is never dropped or treated as empty. **Export-mark write (S-11):** rewrites only `exportedAt` (`bytes` byte-identical) and is read back; on write or read-back failure the original record stays byte-identical. If the loser equals a slot copy by **`sum` + state** (HoQA nit: `savedAt` ignored), it is already preserved: no write, go to 4;
  3. write the loser to the target slot and **read it back** (byte-equal). **Replace (both slots full, M-3):** **occupied-tmp guard (M-4):** if `diverged_tmp` already holds a copy, first run the sweep's verified-duplicate delete on it; if tmp is still present (unique or unverified), the replace is **not attempted**: `save_recovery_slot{slot:'tmp', action:'write_failed'}`, the loser store is untouched, the diverged notice is shown (S-7: `write_failed` is emitted and the notice shown **at most once per load**), and the winner keeps playing and saving to its own store (the loser's store is not overwritten this session). A replace never overwrites an existing `diverged_tmp`. Otherwise, first copy the evicted slot copy byte-for-byte to IDB **`eggfarm/save/diverged_tmp`** and read it back; then write the loser into the target slot (one IDB `put`) and read it back; only after that succeeds delete `diverged_tmp`. If the tmp write/read-back fails, the replace is not attempted (`write_failed` for that slot). If the slot write or read-back fails, restore the old copy from `diverged_tmp` into the slot (read back), then delete tmp; if the restore fails, `diverged_tmp` is kept;
  4. only then overwrite the losing store with the winner.
  There is **no skip path**: every diverged loser is either durably in a slot or its store is not touched. If the slot write or read-back fails, the other slot is tried the same way (if it holds a copy, only when it is the lower-`saveSeq` one; an empty other slot is always tried); if **both** fail, **nothing is overwritten**: both copies stay, the winner is played in memory, its store keeps saving, the losing store is not written this session, and the move is retried on the next load. Every slot write emits `save_recovery_slot {slot: 'diverged'|'diverged2'|'tmp', action: 'fill'|'replace'|'dedupe'|'write_failed'|'sweep', slot_seq, loser_seq}` (the boot sweep emits `slot:'tmp', action:'sweep'` with `slot_seq` = tmp's `saveSeq`, `loser_seq` = null); every divergence emits `save_copies_diverged {winner, winner_seq, loser_seq}`. **Boot sweep of `diverged_tmp`.** The sweep and the diverged notice run **only after the refusal (newer-version) check passes**; a refused load never sweeps, never writes `eggfarm.save.diverged_notice_shown`, and never touches `diverged`, `diverged2` or `diverged_tmp`. The sweep never runs while any slot read-back of this boot is unverified (it runs after the divergence move has finished and every slot written this boot has been read back). It deletes tmp **only after verifying by read-back** that a slot or store currently holds a duplicate of it by `sum` + state; otherwise tmp is the only copy ⇒ if a slot is empty, write tmp there, read it back, then delete tmp; if **both slots are full, keep tmp and show the diverged notice (Export includes it); the sweep never evicts a slot**. The sweep never deletes the only copy. Pre-SQ-1 builds never read, write or delete `diverged_tmp`. Guarantee, stated exactly: a loser is **never overwritten except by a session continuing from it** or after it is durably (read back) in a slot. Because the loser's store is only overwritten after it is in a slot that no old build touches, a rollback to a pre-SQ-1 build can overwrite the stores but never the slotted copy (SK-1 closed). **Residual (recorded, ADR M4-19 rev 4):** with both slots full, a third divergence evicts the lower-`saveSeq` slot copy; that requires three divergences without an Export and is independent of rollback. The diverged notice offers Export whenever both slots are full. **Accepted risk for rc1** (HoE, 2026-10-16): see decisions.md, *2026-10-16 23:58 ADR M4-25*. Export (`[data-testid=diverged-export]`, non-refusal paths) **marks** the exported copies (`exportedAt`, write + read-back of the slot record, `bytes` unchanged) and **never deletes** a copy; exported copies are the first eviction candidates, and the sweep may delete an exported `diverged_tmp`. Reset deletes both slots and `diverged_tmp`.
  **Diverged notice (S-2).** Trigger: a non-refused load after which `diverged`, `diverged2` or `diverged_tmp` holds a copy and the copy-identity hash differs from the once-flag; additionally shown on **every** load while both slots are full (or tmp is kept), regardless of the flag. Copy: "We found an older copy of your farm that didn't match your latest save. Your current farm is safe. You can export the older copy to keep it." With both slots full, add: "Saved copies are full; export now so older copies aren't replaced." Buttons: **Export older copies** (`[data-testid=diverged-export]`) and **Dismiss** (`[data-testid=diverged-dismiss]`). Once-flag (S-5; Code Reviewer (b)): LS **`eggfarm.save.diverged_notice_shown`** = `fnv1a:<8 hex>`, the 32-bit **FNV-1a** of the sorted `sum` values of the **non-exported** copies present in `diverged`, `diverged2` and `diverged_tmp`, joined with `,` (UTF-8). FNV-1a is pure JS and deterministic, so it works without `crypto.subtle` (plain-http LAN previews); no SHA-256 is used for this flag. Comparison: string-equal against the stored value; a stored value without the `fnv1a:` prefix (e.g. an older build's) counts as "different" once, is overwritten with the FNV-1a value when shown, and never re-triggers after that. Plain value, never save data. The notice re-shows whenever the hash differs (a non-exported copy added, replaced or removed). The every-load rule applies while both slots hold **non-exported** copies (or a non-exported tmp is kept). **Export (M-5)** builds one file holding every non-exported slot copy (and tmp) byte-for-byte and marks them **only after the save or share is confirmed**: Web Share API `navigator.share({files})` resolving ⇒ confirmed; rejection (`AbortError` cancel or any error) ⇒ nothing marked. A plain download (`<a download>`) cannot be confirmed by the platform, so the **conservative rule** applies: only if starting the download did **not throw** (S-8; a throw ⇒ error toast, no prompt, nothing marked) the notice shows "Did you save the file?" with **I saved it** (`[data-testid=diverged-export-confirm]`) and **Not yet**; only **I saved it** marks the copies; Not yet, closing the notice, reload or tab close mark nothing. The **clipboard fallback** (S-9, §3a export delivery) uses the same prompt: copies are marked only on **I saved it**. Dismiss marks nothing. Reset clears the flag (in `RESET_KEYS`).
  **Accepted risk (N4):** progress played in a deferral session on a stale copy is dropped when the newer copy wins on the next load.
- **Boot input and deferral session (M4-20, B2; HoE; = spec v1.9 AC (d1)7 "a deferral session never writes the IDB mirror").** The migration input is the **exact bytes and parsed state from the boot read**, carried into the migration. If boot did **not** read IDB successfully (timeout, error, blocked), the migration is **deferred** for the session, even if a later open would succeed, and the **IDB mirror is disabled** for that session (as game.ts already does for a refused newer save): only LS saves. Before the backup, LS main is re-read and compared to the boot bytes; if they differ ⇒ deferral.
- **Fresh farm (M4-22, M3).** A fresh farm on an M4 build (new install, or corrupt-v7 recovery to a fresh farm) is **committed at creation**: marked, a new `migrationId` in `v6BackupId`, no backup written, and it never touches an existing `v6_backup`. So it never enters the migration path and cannot overwrite another farm's backup.
- **Guards (M4-21, M2).** `newerSaveVersion`, `newerStoredVersion`, `validate`, the last-line guard in `save()`, `serialize` and the IDB in-transaction check all take the session's limit (`readMax(b)` for reads, `m4Active ? 7 : 6` for writes) instead of the constant `SAVE_VERSION` (save.ts @ 3351d6c lines 6, 25, 35-36, 76, 116; idb-mirror `seeNewer`). S-1 lists each call site with a test.
- **Order (M4-17).** Validate before backup (load order above). **Restoring `v6_backup` also replaces IDB main** with the restored copy, written with a `saveSeq` higher than any stored copy, so the restore wins every later rank comparison. **Restore source** for rollback/support: LS `v6_backup`, else IDB `v6_backup`, else none; only a committed record whose `raw` passes the v6 `sum` checksum and range validation is restored (the record itself has no integrity field; `raw`'s `sum` is it).
- **Reset (m2).** Settings > Reset clears `eggfarm.save.v6_backup`, `eggfarm.save.migration_attempts` and `eggfarm.save.headroom_probe`, `eggfarm.save.stuck_on_v6`, `eggfarm.save.stuck_notice_shown` and `eggfarm.save.diverged_notice_shown` (all added to `RESET_KEYS`), and deletes IDB `save/diverged`, `save/diverged2` and `save/diverged_tmp` (M-2) and deletes IDB `save/v6_backup` **explicitly** (a keyed delete added next to `clearMirror`; `IdbMirror.clear()` deletes only `main`), so a new farm never inherits the old farm's backup.

### 3d. ACCEPTED (HoE, 2026-10-16 22:11; ADR M4-24): M4-A commit is localStorage-only
**Design (adopted for M4-A; supersedes the IDB-backup parts of §3c, which stay as the recorded alternative):** during M4-A the backup and the committed save are written to **localStorage only**. IDB is **read-only** for the boot read and the newer-save/rank check (a successful boot read is still required, else defer, M4-20); the IDB mirror is paused from boot until the commit and resumed only after the commit is confirmed by an LS read-back.
- **Removes:** the IDB `v6_backup` record and its conditional put; the `idb_write_timeout` path; the per-store (`ls`/`idb`) abort and partial-backup cleanup paths (M4-13 reduces to "remove my LS record"); the keyed IDB delete on Reset for `v6_backup`; the IDB half of `commitWrite`; roughly half of the S-3 test matrix.
- **Adds risk:** (1) the backup has one copy: if the browser clears localStorage, the pre-M4 backup is gone (main still survives via the resumed IDB mirror, as today). (2) Quota: LS holds main + `.bak` + backup, about 3 save copies (saves are a few KB against a ~5 MB origin quota); M4-23 drops the backup before a normal save can fail on quota.
- **Safe?** Yes, in my view: no path writes a migrated or stale state over a newer IDB copy (IDB is never written during the attempt), the rank rule and the boot-read requirement still protect IDB-only newer saves, and the backup is a rollback aid, not the player's live progress. **Adopted.** Conditions (HoE):
  1. **LS headroom check before the attempt:** free localStorage space must be **≥ max(2 × (new save bytes + `v6_backup` record bytes), new save bytes + backup bytes + 64 KiB)** (satisfies spec **v1.10** AC (j) near-full storage and HoE 22:20), verified by a **trial write** of that size under the scratch key `eggfarm.save.headroom_probe`, removed in a **`finally`** block. Any leftover probe key found at boot is **deleted** (migration path; never on the refusal path) and is in `RESET_KEYS` (N3), so a close between write and remove cannot leak it. If it fails ⇒ deferral `save_migration_aborted {store: 'ls', reason: 'quota_headroom', attempt_count}` (+1), stay v6. **Main, `.bak` and telemetry are never dropped to make room.**
  1a. **Pre-commit read-back (HoQA MUST 1):** the LS-only commit (marker / v7 write) happens **only after** the LS `v6_backup` record is read back and its `migrationId` equals the pending `state.v6BackupId`. Otherwise ⇒ M4-12 abort: stay v6, no marker, `save_migration_aborted {store: 'ls', reason: 'readback_mismatch', path, attempt_count}`. This pre-commit read-back is separate from the post-commit read-back in condition 3.
  2. A successful IDB boot read is still required; unknown (timeout, error, blocked) ⇒ deferral (M4-20).
  3. The IDB mirror resumes only after the commit is confirmed (spec v1.10 AC (k): zero IDB writes during the M4-A attempt): LS main read back and byte-equal to the committed raw, and the LS backup record read back with the matching `migrationId`. Until then IDB gets no writes.
  **Mirror after a non-IDB abort (N6):** after any failed attempt that is not an IDB-unknown deferral (aborts `readback_mismatch`, `commit_write_failed`; deferrals `quota_headroom`, and `idb_main_changed` only when that IDB re-read succeeded), the mirror **resumes on the next normal save** (not immediately) and mirrors v6 saves for the rest of that session. After an IDB-unknown deferral (`idb_timeout`, `idb_read_error`, `idb_blocked`, or `idb_main_changed` from a failed re-read) it stays off (M4-20).
  4. **Follow-up S-4:** at the real v7 bump, restore the second backup copy in IDB (`save/v6_backup`, §3c protocol), so the v7 save has two backup copies.
  Under §3d, the §3c IDB-backup rows (IDB `v6_backup` write, `idb_write_timeout`, per-store `idb` aborts, IDB Reset delete of `v6_backup`) apply from S-4, not to F-0/S-3. Spec v1.10 (HoP 22:13) moved the M4A-31(f)1/(h) IDB backup-write rows and `idb_write_timeout` to S-4.

### 3b. Zero-writes rule (HoQA ruling; QA guard ZW-3..6; applies to S-2, ZW-2, flag-off v7 refusal)
Key names from code on main `a01faea`. During a refused load (newer save, or flag-off + v7), through autosave, `pagehide`, Export and a second tab:
- **Must stay byte-identical (or stay absent):** `eggfarm.save` (`SAVE_KEY`), `eggfarm.save.bak` (`BAK_KEY`), `eggfarm.save.v6_backup` (once it exists), every `eggfarm.save.corrupt.*` key and `eggfarm.save.corrupt.index`, `eggfarm.ui` (`UI_KEY`), and IndexedDB `eggfarm`/`save` keys `main`, `v6_backup`, **`diverged`**, **`diverged2`** (the two recovery slots) and **`eggfarm`/`save`/`diverged_tmp`** (IDB replace staging key, M-3); each holds a full save string by design.
- **May be written:** only these localStorage keys, exactly (grep of `setItem` in src/ @ `a01faea`; no wildcards): `eggfarm.lease` (`LEASE_KEY`, tab-lease.ts), `eggfarm.tab` (`TAB_KEY`, tab-guard.ts), `eggfarm.telemetry` (`TELEMETRY_KEY`, telemetry.ts; the only telemetry key). **Allowlisted from S-3 (spec v1.7 (d1), M4-24):** `eggfarm.save.migration_attempts` (plain integer), `eggfarm.save.stuck_on_v6` (`1`) and `eggfarm.save.headroom_probe` (trial-write filler) are known keys, but the refusal path **never writes any of them**, `eggfarm.save.stuck_notice_shown` (`1`, the stuck notice's show-once flag; own key, not `eggfarm.ui`) likewise, and **`eggfarm.save.diverged_notice_shown`** (allowlisted LS key: a plain hash string of slot/tmp checksums, the diverged notice once-flag, **never save data**) likewise; so during a refused load they must stay byte-identical or absent; none of these LS keys may ever contain a serialized save object (same rule as below; the IDB keys `diverged`, `diverged2` and `diverged_tmp` are exempt because they are save copies by design, and they are in the byte-identical list above). **Telemetry has no IndexedDB store:** the only IndexedDB database the code opens is `eggfarm` (`IDB_NAME`) with the single object store `save` (`IDB_STORE`), keys `main` (and `v6_backup` from S-3), `diverged` and `diverged2` (the two recovery slots) and `diverged_tmp` (replace staging), each a full save string, SQ-1, all in the byte-identical list for refused loads. Any other IDB database, store or key appearing is a FAIL. The refusal path never runs the divergence move and never writes or clears `diverged`, `diverged2` or `diverged_tmp` (Export included). On a non-refused load there is no skip: the loser fills an empty slot or replaces the lower-`saveSeq` slot via `diverged_tmp`; if no slot write succeeds, the loser's store is not touched (`save_recovery_slot{write_failed}`). (`eggfarm-recovery-closed` is a DOM event name and `eggfarm-save` / `eggfarm-tabs` are BroadcastChannel names, not storage.)
- **No serialized save in an allowed key.** A *serialized save object* is any JSON object (at any depth, or any string that parses to one) that has **all three** of `version`, `savedAt` and a `state` object, i.e. the `serialize()` shape `{"version","savedAt","sum","state"}`; a raw copy of `eggfarm.save`/`.bak`/`v6_backup` bytes also counts. **Telemetry event snapshot fields are allowed**: scalar fields such as `farm_level`, `hens_level`, `egg_value_level`, `collection_level`, `coinsBefore`, `newLevel`, `cost`, `refund_cents` (§5) are not a save copy, as long as no event carries a `state` block next to `version` and `savedAt`.
- `eggfarm.install_id` (`INSTALL_ID_KEY`) may only be **created if absent**; an existing value must stay byte-identical.
- sessionStorage `eggfarm.playHere` (main.ts tab-takeover flag) is outside localStorage and not a save; it is not asserted.
- Any other key appearing is a FAIL. S-2's own test must assert exactly this list, so S-2 cannot pass while failing QA's guard.

## 7. Architecture risks
1. **Version confusion (v4/v5/v6/v7)** across docs → wrong migration target. Mitigation: ADR M4-1, fix proposal text.
2. **m4a-tracks is 19 commits behind main's save work** (based on `4aadcbf`, before save v4 + dialog); `merge-tree` shows a conflict in
   `src/ui/styles.css` and semantic overlap in save.ts/game.ts load path. Rebase (v2) must re-verify flag-off golden against *a01faea*, not 4aadcbf.
3. **One-way door (reduced by 9.2):** only M4-on builds write v7, and those keep the committed `v6_backup` until Latest. Remaining risks:
   - rc1 builds opening a v7 save must write nothing (S-2 ships on main first);
   - dual write versions add code paths, each covered by a write test;
   - **M4 progress is not reachable from a flag-off build** (refused, not lost): the v7 save stays intact, `v6_backup` is the escape hatch, export works.
4. **Backup storage quota:** the backup doubles the save footprint. On failure the migration aborts and the player stays on a normally saved v6, retried next load (ADR M4-12). Risk: a player near quota never migrates. Watch `save_migration_aborted` in playtest telemetry.
5. **Migration needs balance** (price-matched search depends on economy.csv); a later CSV change silently changes migration output for not-yet-migrated players. Mitigation: freeze the v6→v7 price table as a fixture snapshot in the migration test.
6. **payout.ts base price** must come from `salePriceCents` (comment in tracks.ts) — fix/rc1-qa-bugs branches may reintroduce direct `eggPriceCents` calls. Add a grep/unit guard.
7. **UI churn in app.ts** (65-line diff, shared with rc2 UI work by e80556fd) → merge conflicts. Keep M4 UI in `tracks-ui.ts`, app.ts only wires.
8. **Watch: the WebKit 375px sideways-scroll flake** (rc0 Bug9 farm tab 375×812/375×600, 195/197 once on X-1, rerun 197/197). If it recurs, treat it as a real issue, not a flake.
9. **TR-5 known FAIL** could block ship; gate classified reporting until Economy decision.
10. **`?marketSeed` honoured in release builds** (src/main.ts:83 on main): out of scope for M4; owner Features 95daf662 to gate it to dev/QA builds.
11. **No IDB backup in M4-A (M4-24) + LS lazy flush:** M4-A keeps one backup copy (LS). A browser that persists main before the backup could leave a committed main with no backup, with or without IDB; and a same-page read-back does not prove the write reached disk. Accepted until S-4 restores the IDB copy; watch `save_migrated.backup_stores`.
12. **Deferral progress loss (N4):** accepted. (N1 stale-v6 rank is fixed by `saveSeq`, SQ-1 on main + M4-19.)
13. **Third-divergence slot eviction (ADR M4-25, accepted for rc1 by HoE 2026-10-16):** with both slots full, a third divergence before any Export evicts the lower-`saveSeq` slot copy, possibly the only copy. Mitigation: the diverged notice shows on every load while both slots are full, with Export. A failed replace never loses the old copy (`diverged_tmp`, M-3, ADR M4-19 rev 5), and a replace never overwrites an occupied `diverged_tmp`: a unique or unverified tmp blocks the replace (`write_failed`, loser store untouched, notice; M-4, rev 7). Export only marks copies (`exportedAt`) after a confirmed save/share and never deletes; exported copies are evicted first (M-5, rev 8). Post-rc1: telemetry when both slots are full (status.md).
