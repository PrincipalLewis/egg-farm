## Verdict: HOLD. 1 Major, plus 1 spec conflict that needs a ruling
### MAJOR P46-M1: EXP-b, focus never returns to the Upgrades tab
- `src/ui/tracks-explainer.ts:24` `close()` removes the card and doesn't restore focus. On open, focus moves to Got it (`:31`). Esc closes it (`:27`), and Enter activates the focused button (`:29`). After either, focus is lost to `<body>`.
- Fix (trivial): save `doc.activeElement` before `focus()` and, in `close()`, focus the active Upgrades tab button (fall back to the saved element), with `{preventScroll:true}`.
### SPEC CONFLICT P46-X1: EXP-a, does the dismiss tap pass through?
- The code passes the tap through by design: `tracks-explainer.ts:25-26` uses a capture `pointerdown`, closes, and doesn't call preventDefault, so a Buy under the tap still fires.
- **m4a-spec §11 (v1.3) requires exactly this**: "The dismissing tap passes through to the game and is never swallowed". The checklist's EXP-a (04:34) says the opposite: "doesn't pass through… first tap never buys".
- The code matches the spec, which is the source, so I am **not** counting it as a Major. HoA&UX/HoP need to rule. If EXP-a stands, the fix is to call `e.preventDefault(); e.stopPropagation()` in `onAny` and also swallow the follow-up `click`.
