## 2. Behaviour with `m4.flags.bestBuyV2` = 1 (and `m4.enabled` = 1)
Terms (unchanged from v0.3 §5(g) and the stopgap §2): **meaningful row** = an offered row whose key is FARM, W1, W2, W3 or W4 (exempt; Farm's single-step gain is negative by design, e.g. −0.0125 $/s at the L17 fixture), **or** whose `optionGain(s, b, key).gain > 0` ($/s, `assumeWorking: true`, ε = 0). **Zero-gain row** = any other offered row (gain ≤ 0, negatives included). Generic rule, no `key === 'COLL'` hard-code. Offered set = `options()` (unchanged: MAX, caps, locks, `Max for this farm`, R11 rows are never candidates).
- **2.1 BBv2-1 Zero-gain never ranked.** In all four paths of §1, zero-gain rows are removed from the ranked set **before** the pick (and before affordable-first). The hint, the highlight, the next-goal pool, the tracks highlight and the bot rank meaningful rows only. A zero-gain row may be the strip target (never ★) only when **no meaningful row is offered** (today only after Farm L30 = MAX).
- **2.2 BBv2-2 Hysteresis never protects a zero-gain pick.** Follows from 2.1 (a removed row is not `keepable`, `pick-hysteresis.ts:59`), stated so a test pins it: switching away happens on the next evaluation without the 0.9× bar or the 2 s hold.
- **2.3 BBv2-3 ∞-tie.** When the best payback in the ranked set is ∞ (all tied at ∞), FARM wins, then BUY_ORDER; cost never decides an ∞-tie. **Finite ties keep today's rule** (lower cost, then BUY_ORDER), so meaningful-vs-meaningful picks are unchanged.
- **2.4 BBv2-4 Dead-zone display.** When no meaningful row is affordable, the hint is the best-payback meaningful row (today's `bestOf(rows)` fallback applied to the filtered set; ETA does not enter the ranking) with `affordable: false`, so ★ is null and the strip shows its existing unaffordable countdown status (`~<n> min <n> s` format, `next-goal.ts:87-89`). ★ stays affordable-only (F4-13).

## 4. Edge cases
1. **All offered rows zero-gain after Farm L30 (MAX).** No meaningful row is offered (FARM gone; workers hired; Grader maxed). zeroGainUi = 1 (ship): ZG rows are filtered first. If every offered row is ZG-zero (no Δincome and no Δcapacity), the UI picker is empty and the strip takes its existing no-pick path (`selectGoal(…, undefined, null)`), or BR-BB4 with breeds on. **(v1.0.5)** A row that BBv2 counts as zero-gain but that has Δcapacity > 0 (e.g. a capacity-only HENS milestone, §2.7) survives the ZG filter and can be the hint. It is then shown **without ★** by the mark-null net. That is intended: the strip still points to a real capacity buy, and the ★ ("best buy") stays reserved for income-gaining rows (Architect b6dec409 M2: 18 such states over seeds 1–200). zeroGainUi = 0 (test): the strip may target Collection **without ★** (BBv2-1 allowance); the stopgap mark-null keeps ★ off (the only place the safety net fires, §6). Bot: no meaningful row → the bot's pick is the ∞-tie/zero-gain fallback only if no meaningful key is offered; `pickM4All` behaviour after F30 is a test configuration detail for Econ (the AC7 pacing window ends at F30). If Q-E2 makes COLL meaningful at MAX, it is ranked normally.
2. **Every candidate unaffordable.** BBv2-4: hint = best-payback meaningful row, `affordable: false`, ★ null, countdown status. Bot: wait rule (buy nothing this check-in; `pickM4All` L22) applied to the meaningful set.
3. **Ties.** Finite payback ties: unchanged (lower cost, then BUY_ORDER) in both `better()` and `bestPaybackAmong`. ∞-ties: FARM, then BUY_ORDER (BBv2-3). Ties use the existing 1e-12 tolerance.
4. **Hysteresis 0.9× interaction.** Between meaningful rows unchanged (M4A-41). A zero-gain current pick cannot exist (filtered), so the C4 lock can't occur. A row that turns zero-gain while shown (e.g. after a level change) leaves at the next evaluation with no hold (E17-equivalent). A row that turns meaningful (Q-E2 collect binding) enters ranking at the next evaluation and must clear the 0.9× bar like any challenger.
5. **Flag toggling = reload.** The flag is read from balance at boot; no live toggle. A save made with the flag on loads identically with it off (no saved BBv2 state; picker history is not saved, SG-12).
6. **Offline return / Welcome-back.** No BBv2 state persists; the first render after load evaluates fresh (load counts as a change, SG-12). Offline earnings use the live model, untouched by Q-E2.
7. **M4 off (`m4.enabled` = 0).** `flagOn` is false; BBv2 inert; M4-off goldens byte-identical (`tests/m4a-flag-off.test.ts`).
8. **Asleep/unpaid/Paused workers.** Scoring stays on `assumeWorking` (RV-2e); Paused follows HoE Rule 4. Refill hint path (`bestBuyNeedsRefill`) unchanged.
9. **Breeds / hatch / R11 / `Max for this farm`.** Not `BuyKey`s or not offered: never ranked (BR-BB1, BB-6, BB-7). BR-R7b's Farm-soon note uses the live `secondsToAffordSteady`, unaffected.
10. **Fresh save.** Collection is zero-gain from the first tick (C1); the first ★ must be a meaningful buy affordable within 30 s (BB-13; UC17 retired, D-HOP-24-25 Q-H2).

## 3. Why
Vadim's playtest and the Critic's L10+ read (`product/critic/l10-interaction-read-2026-10-23.md`) found dead zones of 56 s at L17, about 2:15 at L28 and about 1:55 at L29, with ★ pointing at Collection, which delays Farm.

  - Its bundle borrows Farm's payback, and affordable-first lets it win.
  - The 0.9× hold then keeps ★ on it. At L17 with $37.3K banked, ★ stays on Collection indefinitely.
  - At L28–29 every option ties at ∞, and the tie goes to Collection as the cheapest.
- **Measured (real sim, from the Critic's L10 save, following ★):**
  - Today: 13 zero-gain buys, L10→L30 in 39:27, with waits of L17 1:21, L28 2:36 and L29 3:48.

  - Worst seed L28–30 under A: 2:54.
- **Why the bot must change too:** D-HOP-2026-10-19-02 defines both pacing bots as ★ followers.
