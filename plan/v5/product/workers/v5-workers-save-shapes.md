## 0. Shared save mechanics (CODE, all features)
- One save key `eggfarm.save`, `{"version":6,"savedAt","saveSeq"?,"sum","state"}`. `SAVE_VERSION = 6` (`src/save/save.ts:7`). There's no v6→v7 migration (`save.ts:74-85`). An old save loads as `{...initialState(b), ...d.state}` (`save.ts:102`), so unknown keys survive the load and are written back.
- Session-only M5 keys are stripped before every write (`save.ts:146` → `m5Persist`, `src/save/m5-fields.ts:43-46`; list `src/sim/m5-state.ts:65-67`).
- Load-time M5 sanitiser: `m5Load` (`m5-fields.ts:56-76`), called once per load at `src/game.ts:94`, **before** the offline grant (`game.ts:100`). It runs only if one of golden/streak/tapCoins/broody/abilities/pause is on (`m5-fields.ts:23`). **rc2Refill, autoRefill and clockWage are not in that list** (build note, gap G-15).
- `validate()` checks only `coinsCents/coop/basket` ≥ 0 and finite, the levels, `customers` (an array) and `workers` (an object) (`save.ts:214-235`). No per-worker field (`energy`, `cdS`, `unpaid`, `wageFracCents`) is clamped on load: **NOT FOUND**.
- **.bak**: `eggfarm.save.bak` is the previous *valid* main, copied on each save once `bakAllowed` (`save.ts:172-183`, `game.ts:259`). Autosave runs every 5 s (`balance.json` `save.autosaveIntervalS` 5, `src/main.ts:148`) and on hide, pagehide and beforeunload (`src/save/autosave.ts`). So .bak is usually one autosave (about 5 s) older than main. A restore picks .bak or IndexedDB by `rankCompare` (`save.ts:353-387`), then goes through the same `validate` → `m5Load` path. Nothing reconciles a restored copy with main.
- **Hidden tab**: while hidden, `save()` writes the **hide snapshot** stamped at the hide (`game.ts:276-277`). On return, a gap ≥ 60 s (`offline.offlineMinSeconds`, `balance.json:160`) drops the provisional hidden sim and restores the hide snapshot (`game.ts:385`), then runs `m5Offline` and pays the offline grant. A gap under 60 s is simulated live (`game.ts:371-381`).
- **Visible frame gap ≥ 60 s** (OS sleep, throttled tab): `frame()` runs `m5Offline` and then **simulates the first 60 s** (`advance(state, min(gap, 60 s))`, `game.ts:424-425`). There's no offline grant for the rest. ⚠ See M-2.
- **Offline (closed game)**: `applyOffline` only adds `pendingOfflineEggs` (`src/sim/offline.ts:20-25`). Workers, `manageCdS`, `wageFracCents` and every M5 sim-clock field are untouched, so they're frozen.
- **Tab sync**: a single-owner lease, not a state merge. `TabLease` (`src/save/tab-lease.ts`) uses a localStorage `eggfarm.lease` heartbeat every 2 s plus the BroadcastChannel `eggfarm-save` messages claim/flush/flushed. The newest tab asks the owner to flush (owner `flushForHandover`: save, then hold sim and saves for 3 s, `game.ts:157`), claims, then loads (`main.ts:81-95`). The old tab deactivates, and every save checks `owns()` first. Without BroadcastChannel the flush request times out after 300 ms (`requestFlush(ms = 300)`, `tab-lease.ts:30-33`, called at `main.ts:82`). The new tab can then load a save up to one autosave old. No `storage`-event state sync exists. `src/save/tab-guard.ts` (storage-event fallback, AC14d) is not imported by `src/` outside itself (**CODE**: grep).
- **Flags**: `m4.flags.rc2Refill/autoRefill/clockWage` exist in `src/config/flags.ts:10` and `balance.json:174-176` (0). The v5 release values are 1 (manifest L104-106). **No sim, state or save code exists for any of the three** (manifest rows 25/26 "not started", `flag-only`; grep of `src/` for charges/regen/refillCharges/chargeProgress/autoRefill/clockWage finds only the flag keys and UI copy).

## 5. Gaps for HoE/Saves (each PROPOSED by PMW; HoE rules on the code shape, Saves QA tests it)
- **G-1 Charge field names and unit. RULED (D-HOE-20261030-20 (engineering/decisions.md L406-420; L408 + 13:45 correction L420):** `refillCharges` MISSING key (new game, first hire, pre-refill v6 save) → starting 2 (`start_charges`); PRESENT but invalid (NaN, negative, non-integer) → 0; over max → max (F-5b); clamped [0, max]. `chargeNextMs` missing/bad → full regen; valid → clamped [1, regen]. Never grants a charge. Supersedes HoE ruling 3; resolves M-1. Where the v1.0 proposal below differs (non-integer floor, above cap → cap), the ruling wins. *v1.0 proposal (record):* top-level `refillCharges?: int [0, charge_cap]` and `chargeNextMs?: int` = remaining ms to the next charge, in [1, `charge_regen_s`×1000], **present only below the cap**. On load (rc2Refill on): `refillCharges` absent → `start_charges`; NaN/non-number → 0; non-integer → floor; above cap → cap. `chargeNextMs` absent/NaN/≤ 0 while below cap → a full interval (no free charge); above the interval → the interval; non-integer → round. At or above the cap → dropped. This keeps HoE's unit (remaining ms) and closes M-1.
