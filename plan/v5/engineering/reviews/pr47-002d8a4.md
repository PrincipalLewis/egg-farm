- **m1 (Minor)** src/save/save.ts:203-204 (`sanitizeLevel`): a level stored as a string, such as `"12"`, or as a negative, null or Infinity becomes 0, and the save then loads as valid.
  - Before this PR such a save was `invalid_state`, so loadSafe fell back to .bak or IDB. Now the next save overwrites main with level 0.
  - This only bites on a checksum-valid save written by a buggy build, which is low likelihood, but it is a silent loss instead of a recovery. Consider coercing numeric strings, or keeping invalid_state for non-numeric types.
  - Repro: `validate(serialize({...s, farmLevel: '12'}))` returns ok with farmLevel 0.
- **m2 (Minor)** tests: the `sanitizeLevels(f.v6State)` call at save.ts:219 is untested. Deleting it leaves all 76 tests green.

- Interaction with the #45 clamp on the base (merged tree):
  - The track costs, `trackEggsPerSec`, egg value and m4OfflineEggs (offline.ts:9) all clamp to `trackMaxLevel` (55).

  - Above-cap levels therefore run at the cap, deterministically. A huge finite level such as 1e300 is kept and runs at the cap.
