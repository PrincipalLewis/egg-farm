## Findings

### M1 (Major). QA-D-1027-GOALPILL CONFIRMED: verify's end-state save has no `tracksV7` marker, so loading it re-runs the M4 price-match migration and verify.png pictures a different farm than verify.json. verify still PASSes.
- **Where:** scripts/verify.ts:71 (`save(mem, { ...run.end, seenTracksExplainer: true }, savedAt, b)`). The root cause is scripts/verify/sim.ts:61: the run starts from `initialState(b, o.seed)`, which has no marker. A real fresh M4 game marks itself in the Game constructor (src/game.ts:87: `tracksV7: 1, v6BackupId: newId()`). On load, src/save/save.ts:104 (`const tracks = m4On(b) && !state.tracksV7`) and save.ts:108 run `migrateStoredTracksV7` (src/sim/migrate-v7.ts:24-36), which re-derives Egg value by price match.
- **Effect (measured):**
  - Stored end state F30/H30/**V30**/C30 loads as F30/H30/**V20**/C30, with `tracksMigrated: true` and a refund of 0. The same happens at 1 h (C25).
  - The screenshot therefore shows the goal pill "Egg value L21 · +6% income / Ready!" and HUD income **+$1.6K/s**.
  - With the marker added (scratch-clone mutant), the same run shows "All upgrades done!" and **+$2.8K/s**: see pr71-31e1538-marker-cmp.png (left: sample, right: marked).
  - verify.json and the goldens are unaffected, and the `build-label` check still passes, so verify exits 0 with a misleading picture.
  - It already produced a false lead: status.md:869 T-goalpill blames src/ui.
- **Rating:** Major, not Blocking. No game code or player save is affected, but the verify evidence artifact is wrong, and PR templates, QA and CCR are meant to cite it.
- **Repro 1 (node):** copy `engineering/reviews/pr71-31e1538-goalpill-repro.ts.txt` to the repo root as `pr71-goalpill-repro.ts` and run `npx vite-node pr71-goalpill-repro.ts` (the imports are repo-relative). It prints `stored {V:30,tracksV7:null} -> loaded {V:20,tracksV7:1} tracksMigrated true`, and the control with `tracksV7:1` stays at V30.
- **Repro 2 (browser):** `npm run verify -- --hours 24` and open verify.png. The goal pill reads "Egg value L21 … Ready!" although verify.json's end eggValue is 30.
- **Fix expectation:** mark the run like a fresh M4 game, either in sim.ts initial state or at the save in verify.ts:71, with `tracksV7: 1` and a v6BackupId that is deterministic (not random) to keep JSON byte-identical. Add a check that fails verify when the loaded state differs from the end state: for example `migrate(JSON.parse(raw), b).tracksMigrated !== true`, plus matching F/H/V/C levels, or a page read-back of the levels. If the marker goes into the sim state, the trace hash and the sample JSON change (expected), but the goldens must not.

### m1 (Minor). verify.png is not reproducible run to run
- **Where:** scripts/verify/shot.mjs:132-141. The fake clock is installed and paused, but the 'Tap to start' click and the `runFor(1500)`/`runFor(800)` steps let in-page timers or real-time work vary.
- **Repro:** run `npm run verify -- --hours 24` twice and `sha256sum verify.png`. Across my 4 runs there were 2 variants: `8cd03190…` (= sample) and `839a3f85…`. The diff (pr71-31e1538-png-nondet.png) covers a "Coop upgraded!" toast, coop 50 vs 19 ready, income $1.6K vs $1.4K/s, a goal-pill text variant and the timer 0:29 vs 0:30.
- **Why it matters:** the DoD only requires JSON, but two attaches of the "same" verify differ, and an inconsistent screenshot is weak evidence. Consider asserting a stable state before the shot or documenting that the PNG is non-canonical.

### m2 (Minor). sanitize() rewrites every username/hostname substring inside the report
- **Where:** scripts/verify/cli.ts:55-58. Any user or host name of 3+ characters is replaced everywhere in the JSON text, including field values and keys.
- **Repro:** `unshare --user --uts --map-root-user sh -c 'hostname working && npx vite-node <script calling sanitize(JSON.stringify({state:"working"}), "/x")>'` gives `{"state":"<host>"}`. A machine whose user or host is "working", "idle", "grader", "sha", "pass" and so on silently corrupts verify.json and breaks cross-machine byte-identity.
- **Today:** CI (`runner`, random host) and the box (`box`) do not collide.
- **Suggestion:** sanitize path-like occurrences only (`/…/<user>/`, `<host>` in URLs), or fail loudly instead of rewriting.

### n1 (Nit). A browser launch failure gives "no screenshot: unknown", and the report still names verify.png
- **Where:** shot.mjs:126 (`chromium.launch` is outside the try, so the crash leaves empty stdout). verify.ts:78 (`|| '{}'` parses fine, so the catch with the stderr excerpt never runs). verify.ts:97 (`file: 'verify.png'` even when no PNG was written; a stale PNG from an earlier run in the same out dir stays).
- **Repro:** `CHROME=/nonexistent npm run verify -- --hours 1` gives exit 1 (correct) with detail "no screenshot: unknown".

### n2 (Nit). leaks() misses some absolute paths
- **Where:** cli.ts:63. The path regex covers /home, /Users, /root and /workspace only, not /tmp, /var, /opt or Windows drive paths. The only way such a path reaches the JSON today is a browser or shot error message in the `build-label` detail.
- **Repro:** `leaks('/tmp/verify-abc/save.json')` gives [].
