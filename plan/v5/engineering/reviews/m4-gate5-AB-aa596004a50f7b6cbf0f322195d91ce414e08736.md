## Findings

### 1. [major] Focus return picks a hidden Upgrades tab, so focus is lost instead of falling back (P46-M1)
`src/ui/tracks-explainer.ts:33`
- **Evidence.** `const tab = doc.querySelector('[data-tab].active'); (tab ?? (prev...))?.focus(...)`. The tab buttons (`data-tab`, `app.ts:97-99`) always exist inside `#p-upgrades`. They are never absent, and one of them always has `.active` (Collection by default). When the Upgrades sheet is closed on mobile, `#p-upgrades` is `hidden` (`app.ts:173`; `styles.css:103` `.sheet[hidden]{display:none}`). Only the docked layout (≥900) overrides that with `display:flex!important` (`styles.css:163`).
- **Impact.** `tab` is non-null but `display:none`, so `focus()` is a silent no-op and the `prev` fallback is never reached. Got it was just removed, so focus drops to `<body>`. This is the usual path: the card appears on the farm screen after Welcome back > Collect, and the sheet is closed. Keyboard and screen-reader users lose their place, which defeats the point of P46-M1. At 1280 (docked) it works.
- **Why the tests miss it.** The unit tests use either a bare `.tabs` fixture (always visible, jsdom has no layout) or no tab at all. The rc0 g5 focus checks (`rc0-browser.mjs`, "close via Escape/Enter") run after the Upgrades panel has been opened at <900. The first Got it close, with the panel closed, asserts nothing about focus.
- **Fix.**
  - Only use the tab when it is rendered, e.g. `tab && !tab.closest('[hidden]') && tab.getClientRects().length`. Otherwise use `prev` (if connected), else the Collect button or nothing.
  - Add an rc0 assertion for focus after the first Got it with the sheet closed.
  - Add a jsdom test with `<div hidden><button data-tab class=active>` that expects focus on `#other`.

### 2. [minor] The Esc/Enter `stopPropagation` is untested, and the existing Esc test cannot detect it
`tests/m4-exp1-explainer.test.ts:98`, `src/ui/tracks-explainer.ts:37`
- **Evidence.** The Esc check dispatches a keydown with `target === document`. There the explainer's capture listener and `app.ts:285`'s bubble listener are on the same node and both fire at target, so `stopPropagation` would not suppress the app handler even if it were correct. Nothing asserts that the Upgrades sheet or modal stays open after Esc closes the card. The focus tests use a bare fixture with no app listener.
- **Impact.** Deleting `e.stopPropagation()` (the "Esc closes only the card, not the sheet behind it" claim) leaves every test green. The `Enter && e.target === ok` guard is also never tested negatively (Enter on another element must not close the card).
- **Fix.**
  - Mount the app, open the Upgrades panel, show the card, then dispatch Escape on `document.body` or the Got it button.
  - Expect the card to be gone and `#panel-layer` to still have `.open`. A second Escape should then close the panel.
  - Add Enter on a non-ok target (the card stays).

### 3. [minor] The swallow test only exercises `btn.click()`; the rest of the D-07 contract is unasserted
`tests/m4-exp1-explainer.test.ts:84-101`
- **Evidence.** The test covers only Buy and only a programmatic `click()`. That is enough to fail an implementation that lets the first Buy through. It does not cover:
  - a dismissing tap on Collect or on a non-interactive area (card closes, no action);
  - `pointerdown`, which must NOT be swallowed. The old test asserted `defaultPrevented === false`; the new one dropped it;
  - `defaultPrevented` / `stopPropagation` on the swallowed click;
  - a tap inside the card not closing it (other than on the button).
- **Impact.** Moderate regression risk. Someone can switch back to `pointerdown` or `touchstart` and the test stays green unless the app uses those for Buy.
- **Fix.** Add the cases above. The test also edits `modal-layer` by hand (`classList.remove('open')`) and leaves `modalKind==='welcome'`. Collecting through the Collect button is a more honest setup.

### 4. [minor] Held-toast replay loses placement and ordering semantics, and an already-visible toast overlaps the card
`src/ui/app.ts:158-160`
- **Evidence.**
  - `heldToasts` stores `[text, atHud]`. On `EXP_CLOSED` only `q[0]` keeps its `atHud` flag. `q.slice(1)` goes into `toastQ`, which always replays with `showToast(nx, true)` (the HUD position). A held non-HUD toast (the one placed below the queue strip, e.g. the F1 case) can therefore land in the wrong place.
  - The held toasts are pushed after whatever is already in `toastQ`, but `q[0]` is shown first, so the order is not preserved.
  - A toast that is already `.show` when the card opens, or that is showing when the card appears after the ≤1 s modal retry, stays visible for up to 1.3 s on top of the card. It is not hidden by `explainerOpen()`, and the toast is not forced hidden when the card opens.
  - Held toasts can be stale (up to 8 s old), and error or feedback toasts are delayed behind the card.
- **Impact.** Brief visual overlap and rare mis-placement. The G5 check ("toast held, no overlap") passes vacuously if no toast is up, because of `!toastShown ||`.
- **Fix.**
  - Keep the flag on every held entry (make `toastQ` hold `[text, atHud]`, or play held entries through the same path).
  - Put held entries ahead of or behind `toastQ` in a defined order.
  - Optionally hide the current toast when the card opens.
  - Add a unit test with two held toasts that asserts order and `atHud`.

### 5. [minor] "Never two dialogs" does not cover the recovery or save-recovery path
`src/ui/app.ts:693-704`, `src/ui/tracks-explainer.ts:23,27`
- **Evidence.** `modalOpen()` only looks at `#modal-layer.open`. In the recovery path (`showRecoveryDialog(...).then(... showWelcome())`), line 704 `if (g.tracksMigratedWithBackup) showTracksExplainer(g)` runs synchronously while the recovery dialog is up and before Welcome back has been shown. The card therefore appears on `<body>` next to the recovery dialog. The recovery dialog's inert list is `[root, modal, toast]`, so the card is not covered. When the recovery dialog closes, `showWelcome()` then opens a modal under the already-open card.
- **Impact.** Rare (backup-migrated and recovery together), but it violates the stated invariant, and the card's 8 s timer and focus steal also run against the recovery dialog.
- **Fix.** Gate on `recoveryOpen` as well (or call the explainer from the recovery `.then` after `showWelcome`). Also treat the onboarding layer as "modal open" if that case can occur.

### 6. [minor] The swallow listens on `click`, not `pointerdown`; iOS Safari may not deliver `click` for taps on non-interactive areas
`src/ui/tracks-explainer.ts:36,39`
- **Evidence.** The previous version used `pointerdown`. Now `doc.addEventListener('click', onAny, true)`. On iOS Safari, taps on elements that are not "clickable" (no handler or `cursor:pointer`) historically do not generate `click`. A document capture listener is usually treated as sufficient, but this is a known quirk.
- **Impact.** PLAUSIBLE: on real iOS, a tap on empty farm background might not dismiss. The card then still times out at 8 s, so this is not a hard failure. Scroll or drag gestures also no longer dismiss, which is a behaviour change from "any tap". Because `pointerdown` is no longer intercepted, any `pointerdown`/`touchstart` handlers still fire on a "swallowed" tap (today only the queue-chip handler `app.ts:212`, which is harmless because its `click` is swallowed).
- **Fix.** Verify on a real iOS device or WebKit. If it is flaky, add a `pointerup` or `touchend` listener that closes without swallowing, or keep a `pointerdown` that sets a "swallow next click" flag.

### 7. [nit] `close()` steals focus on timeout and on outside tap, whatever the cause
`src/ui/tracks-explainer.ts:33`
- After the 8 s timeout, if the user has tabbed away from Got it, focus is yanked to the tab. After an outside tap, the focus the tap gave to the tapped control is replaced. Only restore focus if `doc.activeElement` is Got it or `body`.

### 8. [nit] Dead `nonmodal` (variant C) code in `rc0-browser.mjs`
`scripts/rc0-browser.mjs` g5 section (`G5MODE`, `MODE === 'nonmodal'`, the `'card'` close path, `.collect, #collect, button.collect`)
- The product has no variant C, so `G5MODE=nonmodal` would fail by construction. The decision (D-07, swallow) is made, so this is unused scaffolding in a gate script. Remove it, or label it clearly as decision-record-only. Also, the "toast held" assertion passes when no toast is visible (`!toastShown || !hit`); the following "plays after close" check covers it.

### 9. [nit] `EXP_CLOSED` listener is never removed
`src/ui/app.ts:159`
- `document.addEventListener(EXP_CLOSED, ...)` inside `mountApp` is never removed. Production mounts once. Tests that remount accumulate stale listeners that call old closures, which is harmless today but fragile.
