- Fix: in `run()` / `runM5xCasual` / `windowGate`, throw if `anyM5FlagOn(b)` and `K.on`. Say in the message that the bot models M5 itself. Add a test.
- Severity: HoE may downgrade this to minor if the guard can wait for the first feature PR. I rated it major because O-3 was stated as a must.

**F-3 — minor — The Broody nest clamp (1e15 cents) can't satisfy the `broodyNestScaled` ×10000 representation.**
- Owner: Saves, with Architect.
- Location: `src/save/m5-fields.ts:25,62`; `src/sim/m5-state.ts:53-55`.
- Evidence:
  - `m5Load` allows `broodyNestCents` up to `BROODY_NEST_MAX_CENTS = 1e15`.
  - `m5-state.ts:53-55` says load sets `broodyNestScaled = broodyNestCents × 10000`. At the clamp that is 1e19, above 2^53 (9.007e15).
  - Exact integers hold only up to 9.007e11 cents ($9.0e9). Above that the product silently loses cents.
  - 1e15 itself is safe against 2^53; only the ×1e4 scaling breaks.
- Not triggered today: nothing reads or sets `broodyNestScaled` yet.
- Fix: clamp the saved nest at `Math.floor(Number.MAX_SAFE_INTEGER / 1e4)` (900719925474), or keep the scaled nest as cents plus a fractional remainder. Add a test at the clamp boundary when the Broody PR lands.

**F-4 — minor — `m5Load` sanitises only golden, broody and abilities fields. Pause and streak state is not covered.**
- Owner: Saves.
- Location: `src/save/m5-fields.ts:19,56`; `src/sim/workers.ts` (`Worker.paused`, `callLockoutS`).
- Evidence:

  - `paused` is safe because `isPaused` requires `=== true`.
  - No reader of `callLockoutS` exists yet, so there is no live effect.
- Rollback note, informational: main loads a worker with `paused: true` as an ordinary worker (it ignores the key and writes it back unchanged).
- Fix: when the Pause PR lands, sanitise `callLockoutS` (finite, ≥ 0, ≤ the lockout tc) and `paused` (boolean) in `m5Load`.

**B. Save compatibility**

- Main loads a flags-on rc/v5 save without loss or rejection: `migrate` spreads `{...initialState, ...d.state}`, the checksum re-stringifies identically, and `validate` has no strict key check. `tests/v5-f2-downgrade.test.ts` covers this for LS, `.bak` and IndexedDB. I did not run main itself.

  - `evRngState` must be a non-zero uint32.
  - `broodyHenIdx` must be an integer in 0..11.
  - `abilities` and its per-worker entries must be objects, with `readyAt` clamped to `[now, now+cd]` and non-finite treated as ready.
  - `activeS` is stripped and ends the call as `offline`.

**C. Offline and clock**
- `src/sim/offline.ts` is untouched. With flags off, `m5Load`, `m5Offline` and `m5ShortGap` return their input object, so offline coins are unchanged.
- Flags on:
  - Gaps ≥ 60 s run `m5Offline` before `advance` in `frame()`, and before `grantOffline` in `settleHiddenPeriod`.
  - Gaps < 60 s run `m5ShortGap` after the uncovered advance.
  - A negative gap (clock moved back) skips the frame work and gets focus 0.
  - A readyAt set far in the future is capped to one cooldown on both load and every read (`wallRemainingMs`).
  - Moving the device clock forward skips a wall-clock cooldown. That follows from the spec'd wall-clock design (abilities E2b); nothing in this change can prevent it.
