## Findings

### 1. minor: telemetry still reports `refund_cents: 0` after a real refund
`src/game.ts:226` vs `src/game.ts:222`.
- Evidence: line 222 stores the real refund. Line 226, a few lines below, still hard-codes `refund_cents: 0` in `save_migrated`.
- Impact: whenever a level is clamped (refund > 0), the card tells the player "We refunded +$X" while analytics records 0. The refund can never be measured in telemetry.
- Related nit: `migrateTracksV7(this.state, p.on)` is now called a third time in this function (lines 206, 211, 222), all with identical inputs. Computing it once and reusing it would remove the risk of the copies drifting.
- Fix: `const mig = migrateTracksV7(this.state, p.on)` once, then use `mig.state`, `mig.migrationRefundCents` and `refund_cents: mig.migrationRefundCents`.

### 2. minor: the refund line is lost on the reload-before-shown path
`src/ui/app.ts:702`, `src/game.ts:140`.
- Evidence: `migrationRefundCents` is session-only state, default 0, and is never persisted. The on-load path (`if (g.tracksMigratedWithBackup) showTracksExplainer(g)`, D-HOP-2026-10-19-13) re-shows the card after a reload that happens between commit and first show. In that session the field is 0, so the line is silently omitted.
- Scenario: the migration commits with a clamp and the player is refunded. The tab is reloaded before the card was ever shown, for example while it was deferred by the persist or visibility retry. The card then appears without the refund line, although coins were refunded.
- Impact: edge-case information loss. The path is rare, and the refund is 0 for all current data. Whether §11 requires the line on this path is not stated in this diff, and I did not check the spec text.
- Fix: either record the omission as accepted (the commit message or the spec), or derive the figure on load. For example, persist it alongside `v6BackupId`, or recompute it from the v6 backup record.

### 3. minor: the `game.ts` refund wiring has no test, so a broken implementation passes
`tests/m4-exp1-explainer.test.ts:128-135`.
- Evidence: the new test feeds `showTracksExplainer` a hand-built fake (`migrationRefundCents: refund`). It never goes through `Game.startTracksMigration`. Deleting `game.ts:222` or hard-coding it to 0 would not fail any test. The `refund_cents` telemetry mismatch in finding 1 was also not caught.
- Why it is hard: with current data the refund is always 0 (`migrate-v7.ts:10`). `startTracksMigration` calls `migrateTracksV7` with no `hensMax` or `eggValueMax` overrides, so a test needs a balance whose track max is below the save's `farmLevel`. `m4a-migrate-v7.test.ts:72` already builds such a case against the pure function.
- Impact: the one production line added for this feature is unpinned.
- Fix: add an integration test. Boot a Game on a clamped-balance fixture, run `startTracksMigration`, and assert both `g.migrationRefundCents === want` and that the card shows the line. Assert the `save_migrated` payload as well.

### 4. minor: the g5 "tap pass-through" and "buy through the card" checks do not test pass-through
`scripts/rc0-browser.mjs` (g5 section; the Collect click, the "buy works after/through the card" check, and the comment "re-check a buy registers while it is up on a fresh show").
- Evidence:
  - The Collect click is followed only by `.tracks-exp` count is 0. It never asserts that Collect or Welcome back actually registered. A card that swallows the tap and dismisses itself would pass.
  - By the time the buy is clicked, the card is already gone: the Collect tap dismissed it, and the comment itself says so. The "fresh show" the comment promises never happens. The check named `buy works after/through the card` is only a plain buy on a clean page.
  - So the claim "tap pass-through" in f328d91 is not exercised in a real browser. Real hit-testing, with the card over the row (`position:fixed`, `top:72px`), is exactly what jsdom cannot cover. The unit test at `m4-exp1-explainer.test.ts:84-95` dispatches `click()` straight on the button, so no hit-testing happens there either.
- Impact: the one thing the browser run exists to prove, that a real tap reaches the control underneath, is unproven. Overlap at 360 is plausible: at 360x800 the card is about 220px tall from y=72, and the Upgrades rows begin at a similar offset on the docked layout.
- Fix: with the card up, click the Buy (or Collect) button using Playwright's actionability check, which fails if another element intercepts the pointer. Then assert the effect (`farmLevel + 1`, or the Welcome back dialog closed) and that the card is gone. Re-show the card via the QA hook or a fresh context if needed. Rename the checks to match what they prove.

### 5. minor: the reduced-motion test pins only the OS media query, and fc4b100 finding 3 is still open
`tests/m4-exp1-explainer.test.ts:136-140`, `src/ui/styles.css:517`.
- Evidence:
  - The test regexes CSS text for `@media (prefers-reduced-motion:reduce){.tracks-exp{animation:X .15s ...}}` and checks that keyframes X contain `opacity` and no `scale`. It tests the stylesheet text, not behaviour. Any rewording of the rule (spacing, selector order) fails it, and a wrong rule that still matches the regex passes it.
  - It covers only the OS setting. fc4b100 finding 3 (the in-app Settings reduced-motion toggle, `.reduced-motion` / `.rm`) is untouched in this delta. `styles.css:516-517` is unchanged and still has no `.reduced-motion .tracks-exp` rule.
- Impact: the new test makes the OS-only behaviour look complete when the in-app toggle still plays the 0.9→1 scale pop. This is the same defect as before.
- Fix: add `.reduced-motion .tracks-exp,.rm .tracks-exp{animation:expfade .15s linear}`, and extend the test to assert it. It should also confirm that the selector shape matches the other components' pattern.

### 6. nit: the refund line's icon has no alignment rule, and the layout is unevidenced
`src/ui/tracks-explainer.ts:22`, `src/ui/styles.css:512-515`.
- Evidence:
  - `.tracks-exp-refund` has no CSS. The 16px `<img>` is inline at baseline inside a 16px text `<p>`. When the sentence wraps (about 45 characters in a 268px-wide content area at 360 and 390 widths), the second line goes under the icon rather than hanging, and the icon sits slightly low.
  - The g5 fixture (`m2-rc1-v5-12min.json`) has a refund of 0, so none of the 6 g5 shots shows the refund variant at 360, 390 or 1280. The card grows by roughly 50px with the line. The `top:72px` card is not blocking, but this was not seen.
- Impact: cosmetic, and unevidenced at the three required widths.
- Fix: make `.tracks-exp-refund` a `display:flex;gap:6px;align-items:flex-start` row (or `vertical-align:-2px` on the img). Add one forced-refund shot per width. A QA hook that sets `migrationRefundCents` before `showTracksExplainer` would be enough.

Also, other UI code builds asset URLs through the `A()` helper in `app.ts`; this uses `import.meta.env.BASE_URL` directly.
