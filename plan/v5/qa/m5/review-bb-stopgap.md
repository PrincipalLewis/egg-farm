## 1. Facts from the code that the review depends on
- `optionGain(s,b,key).gain` = `incomePerSec(after, working) − incomePerSec(s, working)`. `incomePerSec` = eggs/s × `priceDollars` − wages, and `priceDollars = salePriceCents/100 × graderMult`. So **gain is in $/s, not cents/s**. v1.1 §2 says "1e-9 cents/s, the optionGain units". The number in code would be 1e-9 in optionGain's units ($/s); the label is wrong, and that matters for anyone building boundary fixtures.
- Collection with M4 on: price doesn't read C, and collect isn't binding on the working model (diagnosis C1/C2). `after` and `now` then go through the same float operations, so Collection's gain is **exactly 0.0**, not a near-zero residue. ε is only a guard.
- `pctOf` (F4-9) shows `'<1'` for **any** gain > 0, with no ε. The ★ needs gain > 1e-9, so a state with 0 < gain ≤ 1e-9 would show "+<1% income" with **no** ★. v1.1's claim that "the ★ and the '+X%' suffix can never disagree" is therefore not strictly true. It's unreachable on shipped data (see §4) but has to be written down. Collection's suffix is `+N/tap` (kind `tap`), not a %, so the "same as the suffix" argument doesn't cover the one row this spec targets.
- `bestBuyMark` is called **four** times in `app.ts`: `prevMark` (:418), the bypass check (:422), `selectGoal(... bestBuyMark(hintPick))` (:424) and `bestChip` (:498). "Two call sites" means two consumers. The SG-5 diff check must allow all four.
- The strip ★ is `<span class="ng-star" aria-hidden="true">` (goal-label.ts:103). The chip is `.best-chip[data-best-buy=KEY]` with an aria-hidden ★ plus the text "Best buy". The description (`#goalDesc`, `goalAria`) starts with `Next goal: best buy, ` when the star is shown (m41-8-best-chip.test.ts:62,79,138).
- **`window.eggfarmQa` setters don't exist at 5d9efa6.** Only `eggfarmQaRecovery` exists (app.ts:705). The X5 setters accepted for M5.0 (`worker.set`, `set.basket/queue/coopEggs/coins/manageCdS`, `frame`, `focus.advance`, `hide/show`, `menu`) only exist in dev and build:qa, and **none of them sets track levels** (F/H/V/C). The F/C fixtures therefore can't be reached in a browser with the hooks alone.
- Flag: `m4On(p) = !!p.m4?.enabled` (formulas.ts:137). `tests/m4a-flag-off.test.ts` already forces `enabled: 0` and hashes the bot, the 10 Hz action trace and the offline grant against a golden.
- No existing event fits the SG-8 field: `goal_tap` (app.ts:444) fires only on tap, as v1.1 says.

## 4. Float-edge analysis (asked in the v1.1 steering)
- **Collection** gives an exact 0.0 because the same operations run on equal inputs (§1), so ε can't be crossed by noise there.
- **Meaningful rows**: the gain is the difference of two incomes. The rounding error is ~1 ULP of the income: about 4.5e-13 at $2.78K/s and about 1.2e-10 at $1e6/s, so it stays under ε = 1e-9 up to ~$5e6/s. On shipped data to L30 (≤ ~$3K/s) the margin is ~2,000×, and real HENS/VALUE gains are ≥ several $/s. **No flip is reachable on M5.0 data.** At L30+ (M5.1, #12), if income passes ~$5e6/s, noise could exceed ε. Then G2's 1e-6 detector catches it, and ε should become relative (gain > 1e-12 × base). Logged for M5.1.
- **Chip vs strip**: both read the same pure function. They can only disagree if they're evaluated on different `g.state` snapshots (renderGoal vs the row render). G5's "compute once per render" closes that gap. It's the same class of bug as CCR #62 m1.

These edits are allowed under SG-5 "plus tests", but the PR must list them: these are M4.1 F4-13 tests, so changing them changes a signed AC.

Separate PRs, each asserted against the base it lands on.
- **Post-Latest patch1 (#69 v2 + asleep hotfix + m-RC1-1 CSS)**: patch1's `incomePerSec` guard is on the live path only, and `optionGain` uses `working`, so a Market Hand that is Asleep or Unpaid doesn't zero the gain and the ★ isn't suppressed by mistake. - **UC17 / BB-13**: no test in `tests/` references UC17. With the stopgap, a fresh save whose first pick is COLL shows **no ★** until a meaningful row becomes the pick.
