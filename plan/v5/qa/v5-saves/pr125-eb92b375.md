## Findings

- **F1–F5 from the a8a1ae8a bar: CLEARED.** See items 4–5. No longer findings.

- **F7 MAJOR (new): `Σ fT ≠ Σ F` at real animation-frame rates (BR-R12b(b) / golden R5f, `Game.frame`).** Introduced by the F1 share in `eb92b37` interacting with the existing frame loop. `game.ts:488-490` sets `focusMs = focusFrameMs(gap)` for *this* rAF and passes it to `advance()`. `advance()` computes `nFocus` / `focusFtMs` from that call's `focusMs` only. `accMs` carries leftover milliseconds so a tick still fires every 100 ms; the unused focus from the frames that only filled the accumulator is dropped. Repro (rebar probe Q7, qa-probe.txt / q7-frame-rate.txt): 60 s attended, `advance(dt, acc, {focusMs: dt})` with `dt = 1000/fps`. 1 and 10 fps: `focusMs = 60,000` PASS. 20 fps → 30,000; 30 fps → 19,800; **60 fps → 9,600**; 144 fps → 3,600. Before the fix, a tick with `nFocus ≥ 1` got `fT = 100` even if the last frame was 16 ms, so 60 fps roughly credited full attended time. Fix direction: carry unused focus across the acc window (so the tick that fires receives the sum of focus in that 100 ms), or have `Game.frame` pass the accumulated focus for the ticks being emitted — not only the last frame's gap.

- **F3-no-literal, CI-blocking (new, MINOR as a tunable; FAIL as a test / hosted ci).** `tickClock(..., tickMs = 100)` added in `eb92b37` (`src/sim/clock.ts`). Repro: `npx vitest run tests/v5-f3-config.test.ts` — `expected [ 'sim/clock.ts:38 100' ] to deeply equal []`. Hosted ci 42731438175 fails on the same assertion; release-build steps were skipped. Fix direction: drop the default and require the caller to pass `tickMs`, or export a named allowlisted constant.
