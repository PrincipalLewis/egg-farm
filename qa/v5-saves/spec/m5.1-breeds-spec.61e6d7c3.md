## 2. Player fantasy
"These are *my* hens." You hatch eggs into named breeds, fill an album, and put three of them on the nest slots to suit how you play: Layers if you keep the farm open, Away hens if you come back later, Broody hens if you like tapping the nest. **Layers like calm hands (rev. 3):** a Present hen's bonus pauses while you're tapping and comes back after a few quiet seconds (BR-R12b), so Broody hens are the tapper's pick.

## 3. Overview of the loop
1. **Hatch** (from F10): pay coins → a 60 s incubation → a reveal of one breed. The roll happens when the hatch starts.
2. **Album:** 8 breeds. A duplicate adds a **star** (max 2). A breed at max stars leaves the hatch pool. After 24 hatches the flock is complete.
3. **Slots:** 1 / 2 / 3 slots at F10 / F14 / F20. Only slotted breeds apply their trait. Swapping is free and instant.
4. **Traits** come in three families, each tied to a context: **Present** (lay while the farm is open), **Away** (offline eggs), **Broody** (Broody nest fill).

### 4.2 Hatching
- **BR-R5 Cost (coins, not eggs) [P]:**
  `hatchCostCents = max(bc_hatch_min_cents, min(planRefCents × bc_hatch_cost_s, floor((farmStepCents × bc_hatch_farm_share_bp + 5000) / 10000)))`
  - The Farm-step term uses the house rounding `floor((cents×bp+5000)/10000)`, not a plain floor (HoE eng review R2). It is exact at 10000 bp today, and stays consistent if retuned.
  - **Guard simplification (HoE eng review §6):** `farmStepCents × share_bp` is always safe (F30: 62,431,600 × 10000 = 6.2e11). So the guard can be a comparison: if `planRefCents > floor(farmBranch / bc_hatch_cost_s)`, take the Farm branch. BR-AC13 then expects the Farm-branch result on the guarded side.
  - `planRefCents = Math.round(incomePerSec(neutral(s), b, {assumeWorking:true}) × 100)`. This is best-buy's planner income (`best-buy.ts`, `income.ts`) on the **breed-neutral** state (§4.6), rounded once, like the HoE 17:18 I_ss float rule.
  - `farmStepCents` = CSV `farm_cost[F] × 100`, the cost of the next Farm step (RC1 `farmCost(F)`). At F30 MAX there is no next step, so row 30 ($624,316, the unused L30→L31 row) serves only as the cap's input. The 45 s branch binds there anyway.
  - **Why coins:** Economy E2 (`economy.md` §4) shows an egg cost at k = 60 s with back-to-back hatches diverts up to 80% of eggs and drops order fill to ≈16%. Economy's own recommendation is coins. The plan's F20+ note says eggs become trivial there. This deviates from plan R2 ("hatch from eggs") and is **accepted by HoP as an L30+ coin sink (D-HOP-2026-10-24-26 #2)**.
  - **Why this formula:** 45 s of planner income at L28–L30 (≈$125K at $2,779.7/s) is 52% / 39% / 20% of the L28 / L29 / L30 Farm step. So it counts as an event under E3 (≥ 10% of the step). The `min` with one Farm step stops a hatch at F10–F24 costing several Farm levels (at F10, 45 s of income = $3,819, which is 2.8× the $1,368 step).
  - **Why planner income and not I_ref:** I_ref drops to 0 while a hired Market Hand is Asleep or Unpaid (X8, Market §4.2). Pricing on I_ref would let a player buy hatches at the floor by letting workers sleep. The planner path uses `assumeWorking` and is the same for everyone at the same levels.
- **BR-R6 First hatch** is free and always a Common (plan #6). It is offered once, at F ≥ 10.
- **BR-R7** Exactly one incubator (`bc_incubators` = 1 [P]). The Hatch button is disabled while it's busy, or when coins < cost. The cost is recomputed every frame. The press charges the cost of the frame it lands in. If coins < cost on that frame, nothing is charged and nothing starts.

  - **Condition:** `secondsToAffordSteady(next Farm step) ≤ 2 × bc_hatch_cost_s` (= 2 × 45 = 90 s today; written as the expression, not a bare 90, and not a new column). `secondsToAffordSteady` is the game's own time-to-afford (`secondsToAffordSteady` in `src/econ/income.ts`, cited by name; HoE: line numbers stale) with its **default income** (not the planner's `assumeWorking` `planRefCents`), on the breed-neutral state (§4.6).   - **(b) The window: integer ms on the focus clock.**

Each tick adds its focus share `fT`: a frame whose cumulative `floor(focusClock × 1000)` advances by F ms (the Broody R7 `dtMs`) gives its ticks, in order, `min(100, F − already given)` ms each. ### 4.7 Offline, reload, hidden
- **BR-R18 Offline (gap ≥ 60 s):**
  - **In `applyOffline`** (the one path for reload and for a hidden tab ≥ 60 s, `game.ts:94,378`), `remainingMs −= awayS × 1000`, using the **same capped `awayS`** the egg grant uses (`offline.ts:23`, clamp to `offlineCapSeconds` 7200).   - If the result is ≤ 0, `revealHatch` runs in the grant and sets **`pendingReveal`** (a `Game` field, like `this.offline`, `game.ts:28,103`). The UI reads it after the welcome-back modal closes; it isn't a notify event, because listeners aren't attached during load. Telemetry goes only through the SimEvent sink.
  - **Tamper:** an invalid or future `savedAt` gives no grant and **no catch-up** (`validSavedAt`, `game.ts:58,94,360`; `save.ts:190`). A clock jump can't gain more than "the hatch completes", which any 60 s absence already gives.

- **BR-R19 Hidden < 60 s:** the sim keeps running, so the incubator advances. Present gets nothing (`focusDt` = 0). Broody follows its own R9.
- **BR-R20 Reload:** the incubator, rng, slots, settle timers and stars are all saved (§6). A reload mid-incubation resumes the same breed with the saved `remainingMs`. Up to one autosave interval of progress can be lost, the same as for every other sim timer.

- **Migration:** absent → `{owned:{}, slots:[null,null,null], incubator:null, settleMs:[0,0,0], flockCompleteLogged:0, hatches:0, pity:0, rng:mixSeed(s.rng ^ K), freeHatchUsed:0}` (`sinceUnlockMs` is optional: absent reads as 0 and is written on the first increment; no `SAVE_VERSION` bump, HoE rev. 7). **Origin (HoQA N3):** `sinceUnlockMs` counts from the later of the F10 crossing and the first flag-on load. If the `breeds` key is created on a load where `farmLevel ≥ 10`, then `sinceUnlockBackfilled = 1` is written at once (and never cleared). Otherwise it is absent (= 0) (a lazy default plus a sanitiser on read, not a `migrations[]` entry) on the first load with the flag on. The rng is **derived** from `s.rng` with `mixSeed(s.rng ^ K)`, so the first rolls aren't the customer-demand sequence, and **`s.rng` is never advanced** (BR-AC2; HoE nit). Flag off never writes it.
- **Why no bump (R5):** SAVE_VERSION 7 would make every M4.1 build refuse the save as "newer", leaving it read-only (`save.ts:87-89`, `game.ts:61`). Older builds keep the unknown key: `migrate` spreads `d.state` (`save.ts:101`), `step` spreads state (`tick.ts:50`), and `flagOffShape` strips only track keys (`save.ts:162-166`).
- **Rate gate (rev. 3.3):** `focusMs` and the counted-tap stamps (BR-R12b (b)) are **not save fields**, and the shape above is unchanged. Every load starts with an empty window, so the gate is open (BR-R12b (c), BR-AC50).
- **`pendingReveal`** is a `Game` field, not saved. A reveal due at load is recomputed by `applyOffline` from the saved `remainingMs`.
- **Code isolation (R4/R6):** all breed code is a no-op when `s.breeds` is absent, the flag is off, or the slots are empty. `initialState` has no `breeds` key.
- **Separate rng:** `breeds.rng` is its own stream, so hatching never shifts `s.rng` (customer and spawn rolls). That keeps flag-on/no-hatch traces identical (BR-BB5).
- Sanitising: §4.8 E10–E12.
