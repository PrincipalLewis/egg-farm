## 2. Code review: N comes from the game's lock rule, with no `?? F+1`
- `src/ui/tracks-ui.ts` `trackUnlockFarm` loops `f = F+1 .. unlockFarmMax(b)` and returns the first `f` where `sim/tracks.ts trackLock({...s, farmLevel: f})` is `null`. Otherwise it returns `null`, which renders **Max for this farm**. `trackLock` uses `trackCap` → `hensCap/eggValueCap` = `min(maxLevel, F + capOverFarm)` from balance. There's no `?? F+1`, no `+1/+3` literal and no farmMax fallback. `trackLockText(need)` just formats N.
- `unlockFarmMax = min(maxLevel, farmMaxLevel ?? maxLevel)`. On main data that's 30.
- `app.ts:497–505`: `cap` + N → `.lock` with aria `{name}, level {L}, locked. Needs Farm level {N}.`. `cap` + null → `<span class="maxed farm-max" aria-hidden>` plus row `role=group aria-label=trackFarmMaxAria` = `{Track}, level {L}. Max for this farm.`. `max` → unchanged MAX.
- Best-buy, the ★ pick and the strip all filter on `!trackLock(...)` (`econ/best-buy.ts:49-50`, `ui/next-goal.ts:24`), so a capped or Max-for-this-farm row is never a candidate. The `best` class is now also gated on `!lock` (`app.ts:503`, see Info-1).

## Findings
- **Info-1 (behaviour change, not a label change):** the PR also gates the row highlight on `!lock` (`best = !lock && rowHl === t …`, `app.ts:503`). On main, a locked or MAX track row could still carry `best` / `best pending` (the glow, plus the ETA hint when pending) while the DualPicker hold still points at it after a state change. In my synthetic dump that happened on 68 rows. This matches B1-10/F4-19's intent and changes no text or aria, but the PR body doesn't mention it. FYI for HoE/HoQA.
- **Info-2 (pre-existing, out of scope):** on the B6B test balance, the real Farm buy gate (`actions.ts buy`) lets Farm go past `farmMaxLevel` up to `maxLevel` (55). This is the known "FARM-past-farmMax" item with HoE (v1.24 header). It isn't reachable on shipped data (farm max = maxLevel = 30). The oracle bounded F' by farmMax 50 per spec. Also seen in passing at F29: the Farm row reads `Hens & Egg value up to L30 → L30`, which is the already-filed M4B-2 cosmetic and not part of this PR.

- **Info-3 (visual, for the UI/Visual Designer / Art & UX, no spec breach):** when the player is broke, the muted `Max for this farm` pill looks almost the same as a disabled, unaffordable Buy button: same pill shape and same Dust fill (Firefox shot `shots/firefox/f20-farmmax-F20-V25-H18-broke-w360.png`, Hens `$4,048.00` directly above). This matches B1-9 as written ("muted MAX styling", Art GO 10:34). I'm raising it only for the #54 re-check sign-off the spec asks the UI/Visual Designer for.
