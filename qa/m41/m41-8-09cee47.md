## Findings

- **M-1 (Minor, pre-existing on main, not a #62 blocker, not introduced by #62): order chips fail label-in-name.**
  - Selector: `#queue > button.chip.arrive[aria-label="Customer"]` (axe target `.arrive.chip[aria-label="Customer"]:nth-child(1|2)`). Rule `label-content-name-mismatch`, impact serious.
  - The visible text is the demand number ("3", "4") but the name is "Customer".
  - Seen in scenes closed-main-with-eggs-orders and open-market: 4 nodes per width at 360/390/430 on 09cee47.
  - **The same 4 nodes per width appear on base dd223f5**, so the issue is classified as pre-existing.
  - Repro: seed 2 orders (demand 3 and 4), run axe with the rule enabled → 2 violations. Suggested fix (owner UI, M4.2 or later): include the visible count in the name (e.g. aria-label "Customer, wants 3").
- **I-1 (Info): CDP name has a double space between the name and level** ("Egg value  L3", from adjacent spans). Screen readers normalise it, so there is no AC impact; the 54118ec and author manifests show the same.
- **I-2 (Info): `#collect` name vs innerText differed once** ("10 ready" vs "11 ready", 360, workers-tab-tired). This was a counter tick between the two reads; the name is content-derived, axe shows 0, and it did not recur at 390/430.
