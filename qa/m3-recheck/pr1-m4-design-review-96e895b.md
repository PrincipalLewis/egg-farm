## Must
- **M-1 (§8 S-4 row, §8 Ordering, §3a.2):** S-4 "Depends on" lists S-1, S-3, S-2 but not ZW-2. HoQA ruled that ZW-2 blocks S-4. Add ZW-2 to the S-4 dependencies and to the merge order, which currently omits ZW-2.
- **M-2 (§3a.2 vs §8 ZW-2/S-2):** §3a.2 attributes the Export button to "S-2" and says "ZW-2 stays expected-FAIL until S-2". §8 makes ZW-2 a separate Saves PR *before* S-2. Pick one, so QA knows which SHA should flip ZW-2 to PASS.
- **M-3 (§3 Tests, "backup failure" bullet):** "dialog once/session → toast; play continues; v7 not committed; succeeds on retry" contradicts ADR M4-12 in the same section, which says to show "Can't save" **only if the normal v6 save also fails**. As written, the test would expect a dialog on a backup-only failure. It must be rewritten to the M4-12 assertions: v6 bytes and no marker, `save_migration_aborted{store}`, a post-load purchase survives a page close, retry next load, per store (ls, idb), no dialog when the v6 save succeeds. Also, §9.1 is still worded "Reuse 'Can't save' dialog". Mark it as superseded for the backup case.
- **M-4 (§3 ADR M4-12, §3a.5):** partial-backup state is undefined. If LS succeeds and IDB fails, the LS `v6_backup` exists but the backup is "write-once, never overwritten". On retry, is the stale LS copy reused, overwritten or removed? Without a defined expected state, the per-store failure test has no oracle. Specify the result (for example: roll back the LS write, or keep it and skip the LS write on retry only if it is byte-equal to the current v6).
- **M-5 (§3 Tests "zero writes (LS, IDB, .bak, 2nd tab)", §8 S-2):** the zero-writes definition doesn't match the HoQA ruling the guard enforces (ZW-3..6). It needs: all save keys incl. `.bak`, `v6_backup`, `eggfarm.ui` byte-identical; allowed writes only `eggfarm.lease`, `eggfarm.tab`, telemetry, none holding a serialized save object or save copy; `eggfarm.install_id` create-if-absent only. Without this, S-2 can pass its own test while failing QA's.
- **M-6 (§1, §4, §6.1; check (c)):** "flag-off build hash matches main" isn't testable as written. The doc only pins a **sim trace hash** golden to main's trace (§6.1) plus a v6 write (§4). §1 says "bit-identical to rc1 behaviour", which is broader. State exactly which hash is compared (trace hash vs a01faea; any storage-bytes golden?), the fixtures and tick count, and that it is re-pinned to a01faea, not 4aadcbf (§7.2). If a build-artifact hash is intended, say so (it can't match, since the code differs).
- **M-7 (§3 Tests, §6, §8; check (d)):** the test plan doesn't map to the ACs. Only a few rows cite M4A-xx (M4A-30/31/33). Add an AC→test→owner/slice table (M4A-27..34 at minimum, plus ADR M4-9/12, 9.7). Also state the QA method for browser tests: 3 engines run **one at a time** under the browser lock, **own ports (never :4173)**, **runtime build-ID check before asserting**. Today the 3-engine requirement only appears for the rollback test (§6.4, S-6) and the rc0 suite, with no port or build-ID rule.

## Nit
- **N-1 (§3 Tests):** label each test by slice (F-0 interim / S-2 / S-3 / S-4). The "M4-on write test: main is v7" and "chain → v7" tests can't run before S-4. At 3351d6c the M4-on expectation is v6 + `tracksV7:1`. The guard already reports these as PENDING-S4.
- **N-2 (§3 Load order):** "if M4 on and v6: write v6_backup once" should be limited to **unmarked** v6 (and pre-S-4 interim). A marked v6 needs no new backup, and write-once makes it a no-op, but say so for the test oracle.
- **N-3 (§5):** `save_migration_aborted {store, reason}` (§3) is missing from the telemetry table and the pinned list. `backup_ok` is still "proposed".
- **N-4 (§3a.3):** "ZW-2's exact v7 bytes" also applies to rc1 refusing any newer version. Say that export returns the bytes of `eggfarm.save` even when the newer copy was found only in `.bak` or IDB (newerStoredVersion checks all three). Otherwise, which copy is exported?
- **N-5 (§3a.2):** `data-version` should be specified as the highest newer version across LS main, .bak and IDB (matches code), so the guard can assert it.
- **N-6 (header):** the title says v0.2.5 while the PR/task says v0.2. Cosmetic.
- **N-7 (QA side, not the doc):** guard defaults `NEWER_SEL='.recovery-layer [role=alertdialog]'`, `NEWER_TXT=/newer/i`, `EXPORT_SEL='button:has-text("Export")'` (script line 191) still predate §3a.2. Update them to `.recovery-layer.newer-save [role=alertdialog]`, the exact title and `[data-testid=newer-save-export]`, and rerun the a01faea baseline (expect the same result, with ZW-2 FAIL).
